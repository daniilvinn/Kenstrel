# Kestrel progress

Working notes for the implementation of [PLAN.md](PLAN.md). One section per phase.

## Decisions (confirmed by the user)

- Scope: phases P0 to P8, then P10. **P9 (whole-disk search) is skipped.**
- P10: 10a (Windows Terminal split) always; 10b (embedded pane) only if the `vt100` /
  `alacritty_terminal` spike renders cleanly; MCP config and hooks are injected **per spawn**
  (`--mcp-config` / `--settings`), never at user scope; **10f headless actions are not wanted.**
- Mouse capture stays off.

## P0: Skeleton

### Done

- Cargo workspace per PLAN section 3.2: `ks-core`, `ks-fs`, `ks-search`, `ks-preview`, `ks-ui`,
  `ks-app` (binary `ks`). `ks-fs`, `ks-search` and `ks-preview` are intentionally empty crates for
  now (later phases). `ks-claude` arrives in P10. Workspace-level `[workspace.dependencies]`,
  `[workspace.lints]` (`unsafe_code = forbid`, `dbg_macro = deny`, `print_stdout`/`print_stderr`
  warn), edition 2021, release profile `lto = "thin"`, `codegen-units = 1`, `strip = true`.
- **ks-core** (no terminal, fs or async deps):
  - `Key`/`Modifiers`/`KeyChord` with a text form (`ctrl-p`, `alt-.`, `space`) and normalisation
    (shift folded into the character; `ctrl-A` equals `ctrl-a`).
  - `Action`: every action of PLAN section 5 as data (59), with a stable id (`cursor.down`) and a
    palette title. Generated by a macro, so the palette, help and docs can iterate `Action::ALL`.
  - Keymap-as-data: `Binding` = key sequence of `KeyPattern`s (`g g`, `ctrl-p`, `m <char>`) to
    action plus optional argument (`tab.goto:3`). `Keymap::resolve(ctx, pending, key)` returns
    `Action | Pending | NoMatch`; `<char>` captures the next key as the argument (bookmarks);
    `Visual` falls back to `Normal`; `continuations()` and `keys_for()` feed which-key, hints, help
    and the palette. Default bindings are the PLAN section 5 table. User overrides
    (`[keymap.<context>]`, value `"none"` unbinds) replace conflicting defaults; invalid entries
    are skipped and reported, never fatal.
  - Modes and overlay stack (`Mode`, `Overlay`, `KeyContext`); the topmost overlay decides the
    keymap context.
  - `AppState`, `Msg`, `Effect`, `update(state, msg) -> Vec<Effect>`. Implemented behaviour: quit
    (`q`, `ctrl-c`, `Q` = quit and cd), cancel/`esc` unwinding (overlay, mode, status), multi-key
    prefixes with a which-key timer, status line with expiring toasts, job registry driving the
    spinner, resize, interrupt. Any other action reports "<title> is not available yet" in the
    status line instead of failing silently.
  - Generation ids (`Gen`, `GenCounter`): stale timer results are dropped in `update`.
  - Config model (PLAN section 9) with serde defaults and validation; unknown keys are rejected so
    typos are caught (the whole file then falls back to defaults with the error shown). The
    commented default file ships as `crates/ks-core/assets/default_config.toml`; a test proves that
    uncommenting every setting reproduces `Config::default()`.
- **ks-ui**:
  - Theme tokens (all 22 of section 4.4) loaded from TOML. `assets/themes/ember.toml` (dark, warm
    terracotta accent `#d97757`) and `paper.toml` (light) are embedded with `include_str!`.
    Users override or add themes in `%APPDATA%\kestrel\themes\*.toml`; a user theme may set
    `base = "<builtin>"` (default `ember`) and only override some tokens. A user file with a
    built-in's name shadows it. `bg = "reset"` in both built-ins: the terminal background shows
    through.
  - Colour depth: truecolor when `COLORTERM` is `truecolor`/`24bit` or `WT_SESSION` is set, else
    mapping to the xterm 256 palette (cube + grayscale ramp, nearest by distance).
  - Main screen render: header (breadcrumb with `~`, middle elision with `…`, left truncation as
    the last resort), separator, empty body, separator, prompt line (accent `›`, pending keys,
    job spinner, status message coloured by level), hint line (hidden when height < 20, shows
    which-key continuations once the timer fired).
  - `insta` snapshots at 80x24 and 160x48 in both themes, plus prompt/status. The snapshot text is
    followed by a style legend (colour runs per row) so colour regressions are caught too.
- **ks-app**:
  - crossterm raw mode + alternate screen via an RAII `TerminalSession`; restore is idempotent
    (atomic flag) and runs from `Drop`, the panic hook and error paths. Mouse capture is never
    enabled.
  - Panic hook: restores the terminal, logs the panic with a forced backtrace, then chains to the
    default hook so the panic prints on the restored screen.
  - Logging with `tracing` + `tracing-appender` to `%LOCALAPPDATA%\kestrel\state\logs`
    (`kestrel.<date>.log`, daily, 7 kept); `KESTREL_LOG=debug` changes the filter. An unusable log
    directory disables logging rather than failing. Nothing is written to stdout/stderr by the
    TUI.
  - Event loop (generic over backend and event stream, so it is tested headlessly): crossterm
    `EventStream` + `mpsc<Msg>` + effect runner; redraw only when dirty and capped at 16 ms
    between frames; 10 Hz spinner tick only while jobs run; resize handled; messages already
    queued are drained before drawing so a burst of input costs one frame.
  - Effect runner: timers spawned as tokio tasks under child `CancellationToken`s; restarting a
    timer kind replaces the previous one; shutdown cancels all.
  - Input: `translate_key` accepts only `Press`/`Repeat` (pure, tested), maps AltGr (reported as
    Ctrl+Alt on Windows) to a plain character.
  - Config loading: `%APPDATA%\kestrel\config.toml`; first run writes the commented default; a bad
    file keeps defaults and the error (one line) goes to the status line for 8 s; paths are
    injectable (`AppPaths::under(dir)`), tests never touch the real profile.
  - CLI (clap): `ks [PATH]`, `--version`, `--cwd-file <FILE>`, hidden `--debug-panic`. The cwd file
    is written (UTF-8, no trailing newline) only on `Q`, per PLAN section 5 (`q` leaves it
    untouched, so the PowerShell wrapper does not `cd`).
  - `ks` refuses to start when stdin/stdout is not a terminal (clear message, exit 1, no side
    effects).
- CI: `.github/workflows/ci.yml` on `windows-latest` and `ubuntu-latest`: `fmt --check`,
  `clippy --workspace --all-targets -- -D warnings`, `test`, release build, `ks` uploaded as an
  artifact.
- `.gitignore`, `README.md` stub, this file.

### Deviations

1. **`clap` added** (not in the section 2 table) for the CLI. Also added: `futures-util`
   (event stream), `tokio-util` (`CancellationToken`, in the table), `tracing-subscriber`
   (needed to route `tracing` to the file appender), `dunce`, `unicode-width` (in the table, used
   from P0), `tempfile` and `insta` as dev-dependencies.
2. **Paths use `directories::BaseDirs`, not `ProjectDirs`.** `ProjectDirs` on Windows inserts an
   extra `config` folder (`%APPDATA%\kestrel\config\`); the plan wants
   `%APPDATA%\kestrel\config.toml`.
3. **Breadcrumb separator is `/` on Windows too** (`C:/Users/me`, `~/projects/...`), matching the
   mock-up in PLAN section 4.2.
4. **Config `[files]`/`[layout]` field names are my choice** where the plan only lists topics:
   `files.show_hidden`, `files.show_ignored`, `files.size_base`, `layout.list_percent`,
   `layout.parent_column`, `editor.open`, `editor.open_at_line`, `ui.which_key_delay_ms`.
5. **`ctrl-i` is not bound**: terminals deliver it as `tab`, which is bound to history forward
   (section 5 lists both).
6. **Hint line content in P0 is just `‹q› quit`** (and `‹esc› cancel` outside Normal mode): hints
   for features that do not exist yet would be misleading. The hint table in
   `ks-ui/src/render.rs` grows with each phase. Which-key currently reuses the hint line; the
   boxed which-key popup is P5.
7. **`docs/keymap.md` is not generated yet**; the generator belongs with the P5 keymap/help work
   (the data it needs, `Keymap::bindings` and `Action::title`, exists).
8. **`ConfigReload` has no default key** (the only action without one); it is reachable from the
   palette in P5 and bindable via `[keymap.*]`.
9. **`q` does not write the `--cwd-file`**, only `Q` does (see above).
10. The panic hook restores the terminal only for panics on the UI (main) thread, so a contained
    panic in a background task does not tear down the running TUI.
11. **Error toasts last 8 s, not 3 s** (PLAN section 4.1): config errors need time to be read.

### VERIFY results

- **crossterm Windows Press/Release**: confirmed in the crossterm 0.29.0 source
  (`event/sys/windows/parse.rs`): key-down maps to `KeyEventKind::Press`, key-up to
  `KeyEventKind::Release`; `Repeat` is never produced on Windows (auto-repeat arrives as repeated
  `Press`). Filtering to Press/Repeat is therefore correct and sufficient.
- **ctrl-c in raw mode**: crossterm's `enable_raw_mode` clears `ENABLE_PROCESSED_INPUT`, so ctrl-c
  arrives as an ordinary key event (bound to quit in Normal). `tokio::signal::ctrl_c()` is also
  wired to `Msg::Interrupt` for the non-raw window (before/after the TUI).
- **One crossterm version**: `cargo tree -d` shows a single `crossterm 0.29.0`, shared by
  `ratatui-crossterm`, so `EventStream` events and the ratatui backend agree.
- **Crate versions** (latest at implementation time, from the registry): ratatui 0.30.2,
  crossterm 0.29.0, tokio 1.53.2, tokio-util 0.7.20, clap 4.6.7, serde 1.0.229, toml 1.1.8,
  directories 6.0.0, tracing 0.1.44, tracing-appender 0.2.5, tracing-subscriber 0.3.23,
  anyhow 1.0.104, thiserror 2.0.21, insta 1.49.0, dunce 1.0.5, unicode-width 0.2.2,
  futures-util 0.3.34, tempfile 3.27.0.
- **Locations on Windows**: `BaseDirs::config_dir()` = `%APPDATA%` (Roaming), `data_local_dir()` =
  `%LOCALAPPDATA%`; confirmed by a real run that created
  `C:\Users\<user>\AppData\Roaming\kestrel\config.toml` and
  `...\AppData\Local\kestrel\state\logs\kestrel.<date>.log` (both removed again afterwards).
  These ignore the `APPDATA` env var (Known Folder API), hence the injectable `AppPaths`.
- **Windows Terminal key conflicts**: nothing in the default keymap uses `ctrl-shift-*`,
  `alt-enter`, `ctrl-,` or `ctrl-tab`.

### Open issues / notes for later phases

- A real keypress-driven session (`q`, `Q`, resize by dragging) could not be exercised here; only
  the headless and panic paths ran in a real console. Worth a manual check on the first
  interactive session.
- P7: `--cwd-file` writes UTF-8 without BOM. Windows PowerShell 5.1's `Get-Content` defaults to the
  ANSI code page, so the documented `k` function should use `Get-Content -Encoding UTF8`.
- Text input widget (prompt/filter/finder fields) is not built; the keymap already has the
  `Prompt`/`Filter`/... contexts with `esc`/`enter` bindings, and unbound keys in those contexts
  are meant to flow to the input widget.
- **Deferred to P5** (palette/help work): a default key and palette entry for `Reload config`
  (`Action::ConfigReload`); generating `docs/keymap.md` plus a drift test against
  `DEFAULT_BINDINGS`; the full hint-line set of PLAN sections 4.1/4.2 (grows with P1 to P5 as
  the actions become real).
- **Deferred to P1**: an update-level test that the captured `m <char>` argument reaches its
  handler (`run_action` ignores `Invocation::arg` until marks/bookmarks exist; the keymap tests
  already cover the capture).
- Start path is made absolute and lexically normalised, not canonicalised, so junctions and
  symlinks stay as typed. `--cwd-file` fails with an error for non-Unicode directory names.
- `Theme` contains a private copy of the raw palette only to support `base` inheritance; if themes
  grow more features (syntect mapping in P2) revisit the representation.
