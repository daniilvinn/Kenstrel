### 1. PLAN 10c senders
- `grep.send_claude` (default key `alt-c` in the grep overlay; no clash: `alt-c` is unbound everywhere, and
  the grep query field only takes text from unbound plain keys). Sends the marked hits (or, with no marks,
  the highlighted hit) as `@path#L<n>` through `Msg::ClaudeSendRange`/`Effect::ClaudeSendRange` (same
  formatter as before, `ks_claude::mention::format_range_mention` = the existing formatter plus a trailing space, so several
  sends stay separate mentions and the user can keep typing; paths with spaces are quoted by the existing rule). The overlay closes and the Claude pane gets focus. Without a running pane: toast "Claude is not
  running (press c to open it)" and the overlay stays open. (`claude::not_running` is shared by all senders.)
- Grep marks: `grep.mark` (`alt-m`, palette row) toggles a mark on the highlighted hit and moves down. Marks
  are `(path, line)` pairs in `GrepState.marks`; a marker glyph shows in the row's left gutter. `alt-c` sends
  every marked hit that is still in the results, one `ClaudeSendRange` (one mention) each. Marks are
  dropped whenever a new search starts (`clear_results`), so they never leak across queries. The grep hint
  bar advertises `alt-m` mark and `alt-c` claude. Snapshots `grep_marked_*` show the gutter glyph.
- Visual lines in the text preview: `preview.select_lines` (`V` in normal mode; palette row) starts a
  selection on the first visible line when the pane shows a plain text result (not markdown, not the
  metadata view, otherwise toast "Line selection needs a text preview"). New key context
  `preview_lines` (`[keymap.preview_lines]` in config): `j/k/down/up`, `ctrl-d/ctrl-u`, `g g`, `G` move the
  end, `esc`/`ctrl-c`/`V` cancel, `C`/`enter` = `preview.lines_send` sends `@path#L<a>-<b>` (one line:
  `#L<a>`) and leaves the mode. The preview scrolls to keep the moving end visible; selected rows are drawn
  on `selection_bg`, the moving end bold. The mode is dropped by `preview_lines::validate` (called from
  `preview::sync`) when the target changes, an overlay opens or the result stops being text.
  With no Claude pane running, `C` shows the toast and keeps the selection.
- Code: new `ks-core/src/preview_lines.rs` (state `LineSelect`, actions, tests); additive edits in

### 2. Link target in the preview header
`name → target` after the name (symlink colour, error colour for a broken link), cut to the room the name
leaves (nothing under 6 cells). The target comes from the engine's `FileMetadata::link_target` (the engine
already stats with `read_link` and strips `\\?\`), so no extra I/O. Snapshots `link_header_*`.

### 3. Owner in the metadata view
`ks_fs::file_owner(path) -> Option<String>` in the win32 platform module (`GetNamedSecurityInfoW` +
`LookupAccountSidW`, `DOMAIN\user`; falls back to `ConvertSidToStringSidW`; `None` for FAT/denied; non
Windows fallback is `None`). `ks-preview` cannot depend on `ks-fs` (cycle through `ks-core`), so
`PreviewOptions.owner: Option<OwnerResolver>` is an injected `fn(&Path) -> Option<String>` (newtype with
`Eq`/`Hash` that ignore the pointer, so cache keys are unchanged). `build_with_meta` calls it only for
`RequestKind::Metadata` (the `i` view), on the previewer worker threads, never on the UI thread.
`ks-app` injects `ks_fs::file_owner`. Tests: win32 unit test, `ks-preview` resolver plumbing test, and a
headless `ks-app` test that shows the owner end to end.

### 4. Cold start
Before: `init_images` queried the terminal (up to 250 ms when silent) before the first frame.
Now: `PausableEvents::deferred(images)` creates NO crossterm `EventStream`; the event loop draws the first
frame, logs `first frame` (`elapsed_ms` since `startup::mark_process_start()`, called first thing in `run`)
and calls the new `Foreground::first_frame_drawn()` hook. `TerminalForeground` implements it by spawning the
`ks-terminal-query` thread: it runs the graphics query (`init_images`) while nothing else reads stdin, then
creates the `EventStream` and wakes the loop (the waker is stored by `poll_next` under the slot lock, so no
wake-up is lost). The loop is therefore never blocked: it keeps ticking, drawing and handling messages
while the query runs; only terminal input is not read until the query is done, so a terminal that never
answers delays input (not the UI) by up to 250 ms once. Keys typed during the query wait in the console
buffer, except that the query's own stdin reader may consume some typed in that window (inherent to the
query protocol; WT answers in a few ms). A foreground program (`Foreground::run`) joins the thread first.
Tests: `foreground::tests` (no stream and no read before the hook, stream plus wake-up after) and
`cold_start.rs` (the first input event is taken only after the hook). WT answers in a few ms. `LoadNavData` runs through `spawn_blocking`, syntect
warm-up on its own thread; neither is awaited.
Image path: the `DynamicImage` clone and `new_resize_protocol` moved off the UI thread (`ks-image-prepare`
thread; `Host.ready` gates drawing; the notifier requests the redraw). The resize/encode already ran on
`ks-image-encode` (ThreadProtocol). Synchronous test host unchanged.

### 5. Preview polish
- Previewer cache invalidation: new `Effect::InvalidatePreview { paths }`, emitted by
  `fileops::finish_job` (one added line) via `preview::invalidate_paths` for created and removed paths. The
  runner calls `Previewer::invalidate` on both previewers; when the shown file (or the shown directory
  containing one of the paths) is affected the request key changes (epoch bump) so the pane asks again.
- Text decoding: UTF-32 LE/BE with BOM (`Encoding::Utf32Le/Be`, labels "UTF-32 LE/BE"); an FF FE 00 00 file
  that is not valid UTF-32 stays binary. BOM-less UTF-16 (NUL-byte heuristic) already existed
  (`sniff_utf16_without_bom`, tested).
- The owner lookup runs on a helper thread with a 1.5 s timeout and honours the cancel token (a stuck
  Win32 call, e.g. a dead SMB share, cannot hold a worker; the helper finishes on its own).
- Invalidation after a job: also drops the cache of the containing directories, matches paths at any depth
  (changed path inside the shown directory, or shown path inside a removed directory) with ASCII
  case-insensitive comparison, and bumps the parent column key too (`ParentKey.epoch`).
- Line selection fingerprints the text it was started on: a reload with other content drops the mode.
- Directory preview git glyphs / child counts: NOT done. The git snapshot in state only holds the children
  of the current directory, so the previewed directory's entries would need an extra `git status` per cursor
  move, and child counts an extra `read_dir` per entry. Not cheap; the header shows the item count.

## Follow-up: move_undo_and_trash_undo
Not a load flake and not caused by this track: it fails on the base commit 5b58d42 too (checked with a `git archive`
copy), but only when other tests ran before it in the same binary. Cause is a test race: the test pressed `u` as soon
as the listing no longer showed `t.txt`, before the trash job finished and recorded its undo entry, so `u` found nothing
to restore (jobs at timeout: Trashing Done, Moving Done, Moving Done; no Restore job). Fix: `jobs_idle().await`
before `u` in `crates/ks-app/tests/fileops.rs`. 15/15 passed in 5 consecutive runs and in the full workspace run.
Product note: undo pressed while the trash job is still running is silently a no-op.
