# Audit fixes A2: routing, listing/git, search, preview/render

Base: 2208fef (branch audit/a2). All 13 findings of audit-B reproduced on the base (none had been
fixed by the earlier fix wave) and are fixed with a regression test each.

## Done (per-finding verdicts)

1. **Filter vs visual mode** (ks-core `search/mod.rs`): still reproduced. `open_filter` now calls
   `nav::leave_visual_mode` (like the file-op prompts); `accept_filter` and `clear_filter` call
   `view.exit_visual()`; `search::cancel` ends a Visual mode first (Esc over a kept filter ends
   the range, a second Esc clears the filter). Test `filter_replaces_visual_mode_without_leaving_a_hidden_range`
   (both paths A and B; fails without the fix).
2. **git status runs repo-configured commands** (ks-fs `git.rs`): reproduced. `git()` now passes
   `-c core.fsmonitor=false -c core.untrackedCache=false -c protocol.ext.allow=never -c
   status.submoduleSummary=false` before the subcommand (so it also covers submodule status) and
   sets `GIT_TERMINAL_PROMPT=0`, `GCM_INTERACTIVE=never`. Review of other executable keys:
   `status --porcelain=v2` runs no diff/filter drivers, no hooks (`core.hooksPath` is for
   commit-time hooks), `core.fsmonitor` is the only program hook; `core.sshCommand` and
   `credential.helper` only matter for network ops, which are never run. User config is kept.
   Test `repo_configured_fsmonitor_is_never_executed` builds a temp repo whose
   `core.fsmonitor` writes a marker file; a control run with plain `git status` proves the hook
   fires (test asserts it, so it cannot pass vacuously), the Kestrel run must not create it.
   `commands_are_quiet_and_lock_free` extended.
3. **Long-path prefix** (ks-fs `platform/win32.rs`): reproduced (single backslash). Fixed all
   three forms to `\\?\`, `\\?\UNC\`; verbatim and `\\.\` device paths are left alone and checked
   before the UNC branch. Tests: prefix unit tests plus a real junction in a >260 char path
   (created with `mklink /J`, skipped if cmd is unavailable) whose `reparse_tag` is now found.
4. **Refresh during streamed listing** (ks-core `nav.rs`): reproduced. `request()` keeps
   `pending_marks` for `NavKind::Refresh`; the refresh success path, when the view was still
   loading, calls `finish_loading()` (clears `reveal`) and `apply_pending_marks`. Test
   `a_refresh_during_the_streamed_listing_keeps_pending_marks_and_finishes_the_view`.
5. **Stale child counts** (ks-core `view.rs`, `nav.rs`): reproduced. New
   `DirView::dirs_to_recount` (same filter minus `children.is_none()`); the refresh path now
   issues `CountChildren` for up to `CHILD_COUNT_LIMIT` dirs regardless of carried-over counts
   (old values still display until the new ones arrive). Test
   `a_refresh_recounts_directories_that_already_have_counts`.
6. **`sanitize_line` panic** (ks-search `grep.rs`): reproduced by reading. New `snap_ranges`
   (clamp, move outward to char boundaries, drop empty) is applied in the valid-UTF-8 branch of
   `lossy_with_ranges` and at the top of `sanitize_line` (which is `pub`, so it is defensive for
   any caller). Additionally each file's search runs under `catch_unwind` (a bug costs the file,
   counted in `errors`, never the worker) and a worker join error produces `GrepEvent::Error`
   instead of a clean `Done`. Tests: fuzz-style sweep over multi-byte samples x many ranges x
   max_chars, byte-regex integration test (`(?-u:\xA9)` on 8 files: all searched, no error).
7. **Brace globs** (ks-search `walk.rs`): reproduced. `split_globs` tokenizer splits on
   whitespace/comma only at brace depth 0. Integration test `brace_alternation_globs_are_one_glob`.
8. **Multi-line regex error** (ks-search `grep.rs`): reproduced. `build_matcher` keeps only the
   last non-empty line without the `error: ` prefix (`invalid pattern: unclosed group`).
   Unit test + integration test. (The suggested render-side newline collapse was not added: the
   engine message is now always a single line.)
9. **Image double draw under overlays** (ks-ui `preview.rs`): reproduced by tracing. The main
   pane skips an `Image` body when `search::preview_rect(state)` is `Some` (the overlay pane then
   draws it alone). Test `an_image_is_drawn_once_per_frame_under_a_finder_overlay` uses a
   thread-local `render_image` call counter (test-only) and fails without the fix (2 calls).
10. **`truncated` flag** (ks-preview `content.rs`): reproduced. Truncation is relative to
    `text_len = min(head.len(), max_text_bytes)`; the full head only feeds sniffing and hex.
    Test `a_text_limit_below_the_hex_size_still_reports_truncation` (fails without the fix).
11. **Hex wide threshold** (ks-core `preview.rs`): reproduced. `HEX_WIDE_MIN_WIDTH` 75 -> 76,
    comment corrected (48 hex cells). Test `hex_rows_never_overflow_the_content_width` at
    widths 60/74/75/76/77/100.
12. **Bidi/format characters in names** (ks-ui `text.rs`): reproduced. `sanitize` now uses the
    shared predicate `ks_search::is_unsafe_char` (now `pub`, plus U+061C added): C0/C1/DEL,
    U+200B/E/F, U+2028..202E, U+2060..2064, U+2066..206F, U+FEFF -> `?`. ZWJ/ZWNJ kept. Also the
    header breadcrumb now sanitises each path segment (it bypassed `sanitize`). List, header,
    preview, finder/grep (`path_spans`), dir rows already called `sanitize`; the tab strip shows
    numbers only.
13. **Markdown quadratic scan** (ks-preview `markdown.rs`): reproduced by reading. `inline()`
    precomputes next-`]` / next-`)` tables (O(1) lookups) and memoises failed backtick-run
    searches per run length, so the whole line is linear. Test with 250k-char pathological lines
    (`[`*n, `[](`, `[`*n+`]`, `[x](`, backtick patterns) with a 5 s bound (takes ~0.1 s total) and
    a behaviour test for links/code.

## Deviations

- `ks-search` moved from `[dev-dependencies]` to `[dependencies]` of ks-ui to share the
  `is_unsafe_char` predicate (workspace crate, no new external dependency). `ks_search::is_unsafe_char`
  is a new public export.
- Esc in Visual mode with a kept filter now ends visual mode first instead of clearing the filter.

## VERIFY results

- Plain `git status` on a repo with `core.fsmonitor` set to a shell command does run it on this
  machine (Git for Windows); with the forced `-c core.fsmonitor=false` it does not.
- `mklink /J` junction inside a 260+ char path: `reparse_tag` via `FindFirstFileW` with the
  corrected `\\?\` prefix returns `IO_REPARSE_TAG_MOUNT_POINT`.

## Flaky ks-app tests (load-induced)

- `invalid_bulk_rename_is_reopened_with_the_file_kept` and the other bulk-rename tests counted
  `kestrel-bulk-rename-*` files in the shared system temp dir, which also sees files of test
  processes running in other worktrees. The fake editors now log the edit file path they are given
  (`<script>.paths`) and the tests assert on exactly those files (`edit_files`, `assert_edit_files_gone`).
- `effects.rs` test `WAIT` 5 s -> 30 s (covers `git_status_*` and `search_files_*`), and
  `persist::the_writer_applies_writes_in_order...` finish timeout 5 s -> 30 s. Timeouts only bound
  failures, so passing runs are not slower.
- Final gates: fmt, clippy -D warnings, `cargo test --workspace` all clean.

  refresh keeps its reveal for the reposition logic). Asserted in the streamed-refresh test.
- Recount cost: `replace_entries` now returns only the stale directories (new, mtime changed or
  unknown); the old count still displays. `dirs_to_recount` removed. Test
  `a_refresh_recounts_only_directories_whose_mtime_changed`.
- `pending_marks` are cleared when a refresh fails without climbing (`a_failed_refresh_drops_stale_pending_marks`).
- grep: cfg(test) hooks (`__file_panic__`, `__worker_crash__`) force a per-file panic and a worker
  crash; tests assert one counted error with the rest of the search finishing, and a `GrepEvent::Error`
  on a worker crash. A panicked file is no longer also counted as searched.
- Visual/filter test split into two focused tests (no hand-set mode).
- Rejected: moving `is_unsafe_char` out of ks-search (ks-search cannot depend on ks-core; ks-ui
  already depends on workspace crates, no external cost). Deferred: the 30s timeout bump is a
  mitigation only (not reproduced under load); the bulk-rename change is the root-cause fix.
