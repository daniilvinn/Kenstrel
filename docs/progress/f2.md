# F2: search freshness, watching, memory, rg ratio

Branch `fix/f2` (base 5b58d42). Gates (`cargo fmt --all`, `cargo clippy --workspace --all-targets -- -D
warnings`, `cargo test --workspace`) are clean. Committed on top of 5b58d42.

## Done

1. **Finder cache freshness (PLAN 6.2).**
   - Reopening a cached root still serves the cache at once (feed thread), and now also starts a
     background re-walk (`FinderSession`, `FinderOptions::refresh_cached`, default on). The re-walk reuses
     the cached allocation of every unchanged path (hash lookup of the folded path), so its transient cost is
     small. When it finishes: new paths are injected into the running session; if something vanished,
     nucleo (which cannot remove items) is restarted from the fresh list with `restart(false)` so the old
     rows stay on screen until the new ones are matched. The fresh list is stored in the cache. A root that is
     not a directory (vanished, unplugged) is never mistaken for an emptied one. The result is applied only
     after the initial feed has finished. `FinderStatus::refreshing` / `FinderSession::refreshing()` report it
     and `busy()` includes it, so the worker keeps ticking and sends the updated snapshot.
   - `WalkCache::apply_changes` now scans newly added directories (also directories moved into the root) with
     the walk toggles of each cached root (hidden, gitignore, include_dirs), on the caller's thread outside the
     cache lock.
   - New `PathChange::Touched(path)`: the filesystem decides (directory: added and scanned; file: added; missing:
     removed). Used for:
     - **file operations**: `fileops::finish_job` emits `Effect::WalkCacheChanges` with `Removed` for the
       job's removed paths and `Touched` for the created ones (`search::cache_after_job`), so destinations
       other than the displayed directory are fresh;
     - **Claude hook events**: the `HookEvent` handler emits `Touched(file_path)` for the main walk cache. The
       Claude host keeps its own cache (it already clears it on hook events and after a TTL), and its
       headless `search_files` sets `refresh_cached: false` so a reply never waits for a re-walk.
2. **Watch the directories of all tabs (PLAN P7).** New `Effect::WatchParked { paths }` (the dirs of the parked
   tabs, one per tab, so at most 8) and `Msg::ParkedDirChanged { path }`. The runner keeps a set of watchers
   (starts new ones, keeps unchanged ones, cancels removed ones; failures are logged, not shown). Core marks
   the matching parked tabs stale (`Tabs::is_stale`) and re-lists them in the background (see Deviations); the tab strip shows a dot (`*` with the ASCII icon set)
   after the number while stale, and activating the tab re-lists it as before (clearing the mark). The effect is emitted
   on every tab switch, new tab, close and results-list tab. The active tab keeps its own `WatchDir`.
3. **Results-list size/mtime.** New `Effect::StatEntries` / `Msg::EntryStats` and `ks_fs::stat_entries`
   (batches of 64, cancellable, off the UI thread via `spawn_blocking`, shares the child-count slot).
   `show_results_list` requests the stats; `DirView::apply_stats` fills size and mtime and re-sorts (keeping the cursor entry) when the sort key is size or mtime.
   Stale generations are dropped.
4. **Memory (PLAN P8, 1M-path cache < 250 MB).** `FinderItem` is now one `Arc<str>` (first byte = kind tag and
   "lossy name" flag, then the relative path). The walk cache and nucleo share the single allocation;
   non-Unicode exact names moved to a side table (`raws`, keyed by the lossy path) that is only consulted
   for tagged items. See Measurements: 301 MB -> 204 MB steady, 330 -> 204 MB peak.
5. **Content search vs rg (P8 budget 1.5x).** Measured, and the engine is faster than `rg`; no optimization
   was needed. See Measurements. New `ks-search/examples/grepbench.rs` (kept; compares with
   `rg -c -S -F`, has `--gen` to build the synthetic tree).
6. **Small items.**
   - `ctrl-r` skips scopes that resolve to a root already passed (the first snapshot of the new session tells
     the root; core advances to the next scope until a different root or four scopes). If all resolve to one
     root the last scope stays.
   - Drives: every drive is queried on its own thread with a 1.5 s overall deadline
     (`ks_fs::drives::query_all`); a drive that does not answer is listed with its type and the text "not
     responding" (`DriveInfo::unavailable`). Hung threads are abandoned, not blocked on.
   - Git status coalescing: a `GitStatus` request for the directory that is already being scanned no longer
     cancels and restarts the scan (under constant churn on a huge repo it never finished). The running task
     records the newest generation, answers with it when the scan ends and scans once more if files changed
     meanwhile. A different directory still replaces the run.

## Deviations

- **Parked tabs are re-listed in the background** (second pass). A watcher event marks the tab stale and core
  issues `Effect::ListParked { gen, path }` with a ticket from the tab's own `list_gen` (each tab has its own
  ticket space). The runner lists it on a separate task (it does not use the single listing slot, so it never
  cancels the active tab's listing). `update` routes `ListingChunk`/`ListingFinished` first through
  `tabs::parked_chunk` / `parked_finished`: the entries collect in the slot (`TabSlot::bg`) and are applied to
  the parked view with `replace_entries` (cursor kept by name), the stale mark clears, and the walk cache gets
  the diff. A failed re-list leaves the mark; activation still re-lists as before. Tests: core
  (`a_parked_tab_is_re_listed_in_the_background`) and runner (`a_parked_listing_does_not_cancel_the_active_one`).
- **Grep root stays the cwd.** PLAN 6.3 gives `ctrl-r` the regex toggle in content search, so there is no scope
  cycle to be consistent with (the finder's `ctrl-r` scope cycle is PLAN 6.2 only).
- **Filter highlight on truncated names**: lives in `ks-ui/src/list.rs` and was already handled
  (`highlight_survives_truncation` exists); not touched.
- `FinderItem` is no longer a struct with public fields: `rel()`, `kind()`, `is_lossy()`; `FinderItem::new`
  takes `impl AsRef<str>`. `FinderItem::from_rel_path` returns the item only (exact non-Unicode names are kept by
  the session). Only ks-search and its examples/benches/tests used the fields.
- `WalkCache::put` is now public (benchmarks and examples fill the cache directly).
- `Effect::StatEntries`, `Effect::WatchParked`, `Msg::EntryStats`, `Msg::ParkedDirChanged`, `DriveInfo::
  unavailable`, `FinderStatus::refreshing` and `PathChange::Touched` are additive. No new `Action`, so
  `docs/keymap.md` is unchanged.

## Measurements

Memory, 1M synthetic paths (45 characters on average), release build, one cached root plus one open
session with the query `handler` (147k matches), working set read from outside the process
(`target\release\examples\mem.exe`, `Process.WorkingSet64` after the probe printed READY; peak =
`PeakWorkingSet64`; the earlier note's 312 MB included the transient input strings, the probe now builds
the items in chunks):

| | steady | peak |
|---|---|---|
| before (`Box<str>` + kind + raw per copy, cache and nucleo each own one) | 301 MB | 330 MB |
| after (shared `Arc<str>`) | 204 MB | 204 MB |

Budget < 250 MB: met with one open session. With the four-root cache limit, a second 1M root costs about
another 100 MB (cache entry only, 16 bytes per item plus the shared string). The nucleo side (its own
UTF-32 column per item) is the remaining half and cannot be shared.

Content search vs `rg 15.2.0` (installed under `target\tools`, not in the repo), best of 5 (3 on the
second corpus), wall time of the whole command, `rg -c -S -F <pattern>` vs the `grepbench` example in the
same machine state; match and file counts are identical in every case:

| corpus | pattern | rg | ks | ratio |
|---|---|---|---|---|
| generated, 20k files, 209 MB | `NEEDLE_MARKER` (7.5k lines) | 269 ms | 116 ms | 0.43 |
| same | `handler` (793k lines) | 277 ms | 163 ms | 0.59 |
| same | `needle_marker` (smart case, insensitive) | 239 ms | 117 ms | 0.49 |
| same | regex `NEEDLE_\w+ line1\d\d\d` | 246 ms | 125 ms | 0.51 |
| `~/.cargo/registry/src`, 27k files, 792 MB on disk | `unsafe` (683k lines) | 426 ms | 285 ms | 0.67 |
| same | `fn main` | 414 ms | 214 ms | 0.52 |
| same | `Windows` | 482 ms | 214 ms | 0.44 |

The rg numbers include process start and PowerShell output handling (about 30 to 50 ms); `rg --stats` reports
0.33 to 0.38 s total on the generated tree and 0.52 to 0.65 s on the registry (single cold-ish runs), so the
conclusion holds either way: well within the 1.5x budget.

## Review pass

Fixed (each with a test unless noted):
- Refresh with removals dropped the exact names of surviving non-Unicode entries: raws are now kept for
  survivors (`a_removal_refresh_keeps_the_exact_names_...`, Windows).
- Parked re-lists piled up: the runner keeps one cancellable re-list per parked path (a newer one, or the tab
  leaving the parked set, cancels it) (`re_lists_of_one_parked_directory_do_not_pile_up`).
- Lazy results-list stats had a shared slot with child counts and were lost on tab switch: own `Slot::Stats`,
  and `resume` of a results tab asks for the stats again (`a_results_tab_asks_for_its_stats_again_...`).
- `Touched` only removes on `NotFound`; other metadata errors leave the cache alone.
- ctrl-r with all scopes on one root now wraps back to the starting scope (test extended).
- A refresh no longer overwrites a newer incremental cache update (`WalkCache::put_walked_if_unchanged`).
- `scan_new_dir` is capped at 200k entries per new directory so `apply_lock` is held for a bounded time.
- Drive query thread-spawn failure lists the drive as unavailable instead of querying inline.
- Memory guard: ignored test `finder_cache_1m_paths_under_250mb` (`ks-search/tests/memory.rs`, measures peak
  working set of the `mem` example; the workspace forbids `unsafe`, so no counting allocator) plus the
  non-ignored `cache_and_matcher_share_one_allocation_per_path`. Release: 210 MB. Keystroke guard 21.9 ms.
- New snapshots: `tabs_stale_*` and `drives_dead_*` (80x24, 160x48, both themes).
- Parked re-list cache diff and the activate-while-in-flight edge are now tested (tabs.rs tests).

Rejected:
- "Newly created directories scanned before filtering": the walk already prunes hidden, `.git`, system names
  and gitignored trees (the `ignore` crate reads parent ignore files); `excluded_by_rules` is a second check
  for the new dir's own ancestors. Only the cap was added.
- `GetDriveTypeW` on the caller thread: it reads the local mount table and does not touch the server.

Deferred (Open issues):
- Healthy drives are still shown together with the dead one after the 1.5 s deadline; showing them early
  needs a two-phase `DrivesLoaded` message. A dead share is marked unavailable and the wait is bounded.
- `scan_new_dir` is capped but not cancellable.
- Timing-sensitive tests (`claude_flow`, `tabs_and_state`, `watcher::a_burst_of_changes_is_one_notification`)
  can fail on a loaded machine; not hardened here. The rg ratio and memory tables above predate this pass
  (memory re-measured: 210 MB).
