## Done

- **Layout** (`ks-core/src/preview.rs` geometry, `ks-ui/src/preview.rs::render_body`): optional
  parent column | list | preview, divided by `│` in the `border` colour. Preview shows at 80+
  columns (`w` forces it on or off at any width; an explicit choice survives resizes), the list
  gets `[layout] list_percent` (40) of the space left after the parent column, a pane that would
  be narrower than 20 columns is dropped (preview first). Parent column (`P`, `[layout]
  parent_column`) needs a 100+ column terminal and shows the parent directory (engine directory
  listing) with the current directory highlighted (`▌`, selection background, bold dir colour).
  The layout is computed in one function (`ks_core::preview::pane_widths`,
  `AppState::pane_widths_at`) shared by `update` and the renderer, and applied in a single
  function `render_body`, so P10's Claude split can be a separate wrapper around it.
- **Preview pane**: header (name, then `[syntax | WxH fmt | ZIP N entries | hint] · size ·
  mtime`, least important segments dropped when narrow), rule, content. Text with line numbers
  in `fg_muted`; markdown (engine spans, no gutter); directory (icon, dimmed names, sizes from
  28 columns, `… and N more`); zip listing; hex view (16 bytes/row from a 76-column pane, else
  8, offset in `fg_muted`, ASCII dim); metadata view (`i`: name, path, type, size with exact
  bytes, created/modified/accessed in local time, attributes, link target, owner when known);
  `Unavailable` shows the reason wrapped in `warning` colour followed by the metadata; empty
  file; images. A result is only drawn when its path is the cursor path.
- **Wiring**: `PreviewState` in `AppState.preview`; `Msg::Preview(PreviewMsg)`,
  `Msg::ParentPreview(PreviewMsg)`, `Msg::ImageReady`; `Effect::RequestPreview{gen,request}`,
  `CancelPreview`, `RequestParent`, `CancelParent`. After every `update`, `preview::sync`
  compares what the pane should show (cursor path, mtime, size, `i`, hidden toggle, pane
  visibility) with what was requested; a difference bumps the generation and emits one request,
  so every way of moving the cursor (keys, refresh, resize, toggles) is covered without touching
  `nav.rs`. Stale results are dropped by generation. Scroll resets per file but is kept when the
  same file is refreshed after an external change (old content stays until the new arrives).
  `J`/`K` scroll by half the visible rows and are clamped to the content (`content_len`).
  Actions `preview.toggle`, `preview.parent_column`, `preview.metadata`,
  `preview.scroll_down/up` were already in the `Action` enum and default keymap (`w P i J K`),
  so they appear in the palette once it lands.
- **Effect runner** (`ks-app/src/effects.rs`): two lazily created `Previewer`s (main pane and
  parent column; a Previewer has one request slot). The sink forwards the engine event 1:1
  (`blocking_send` from the engine's own std threads). The runner holds the syntax palette
  (`set_preview_palette`, called by the event loop from the theme) and maps `PreviewRequest`
  to `PreviewOptions` (limits from `[preview] max_bytes/max_lines`, hidden toggle). The
  syntax set is loaded on a background thread at start (`highlight::warm_up`).
- **Theme syntax tokens** (`ks-ui/src/syntax.rs`): optional `[syntax]` table in a theme file
  (`keyword string comment function type number constant operator punctuation`). Unset keys are
  derived from existing tokens (keyword=accent, string=success, comment=fg_muted, function=dir,
  type=warning, number=symlink, constant=git_untracked, operator/punctuation=fg_dim). `ember`
  and `paper` set them explicitly. A user theme inherits its `base`'s explicit syntax colours.
  `Theme::syntax_palette()` feeds the engine; `Role` spans map to the same-named token, RGB
  spans are converted for the colour depth (`Theme::rgb`, 256-colour mapping included).
- **Images**: `ks-ui/src/images.rs`. Picker created in `ks-app::init_images` right after the
  alternate screen is entered and before input is read (`Picker::from_query_stdio_with_options`
  with a 250 ms timeout instead of the library default 2 s, so a mute terminal costs at most
  250 ms once at start-up), falling back to halfblocks. `[preview] image_protocol = "auto" |
  "halfblocks" | "sixel" | "kitty" | "iterm2"` (new config key, in `default_config.toml`);
  `"halfblocks"` skips the query; any other forced value still queries (for the font size) and
  then overrides the protocol. The decoded `Arc<DynamicImage>` is resized and encoded on a
  worker thread (`ThreadProtocol`), the UI draws what is ready centred in the pane, and the
  worker's notifier turns completion into `Msg::ImageReady` (redraw). Protocol state is a
  process-global in ks-ui; `PreviewState::image_id` is only an opaque handle (changes with each
  new image). When graphics left the screen (image moved or gone) `finish_frame()` tells the
  event loop to `terminal.clear()` and redraw, because Sixel pixels are not erased by
  overwriting cells with spaces. Without an installed host (tests) a synchronous halfblocks
  host is used, so snapshots are deterministic.
- **Tests** (all new, nothing existing changed except one assertion, see Deviations):
  - `ks-core::preview::tests` (15): request on first position, supersede on move, stale drop,
    `w` toggle + cancel, narrow terminals (`w` forces), resize across 80, `i` request kinds,

  - `ks-ui::preview_tests` (21 tests, 46 snapshot files): text (highlighted), text scrolled,

    `paper`; narrow 70x24 hides the preview. Plus: stale result is not shown, results reach the
    screen through `update`, real syntect output coloured with the theme palette, theme syntax
    defaults/overrides/inheritance, role/RGB/256-colour mapping, wide-character clipping, hex
    8/16 wide, word wrap, keypress-to-frame budget. `ks-ui::images::tests` (3), incl. the

  - `ks-app/tests/preview.rs` (8, real engine and files): every kind of file gets its preview,

## Deviations (with reasons)

1. **`ks-core` depends on `ks-preview`** (and `image` as a dev-dependency for one test). `Msg`
   must carry `Arc<Preview>` and `Preview` is the data model; `ks-preview` is terminal-agnostic
   and independent of core, so there is no cycle. `PreviewMsg` is a newtype with a manual
   `PartialEq` (generation, path, `Arc::ptr_eq`) because `Msg` derives `Eq`.
2. **`Gen::raw()` / `Gen::from_raw()` added** (`generation.rs`, additive) to carry generations
   through the engine, which uses `u64`.
3. **Preview state is global to `AppState`**, not per pane/tab. P7 turns the pane state into
   `TabState`; the preview follows whichever tab is active, so P7 must call into the
   `preview::sync` path after a tab switch (it already runs at the end of every `update`) and
   should reset `preview.current/target/key` if tabs show different directories (the key
   comparison makes this automatic: a different cursor path just triggers a new request).
4. **The palette lives in the effect runner, not in the Effect.** `Effect` derives `Eq`
   and must stay free of colours; theme changes (P5) must call
   `EffectRunner::set_preview_palette(theme.syntax_palette())`. Cache keys include the palette
   so no explicit cache clear is needed.
5. **Theme syntax tokens are a separate optional `[syntax]` table**, not extra keys in
   `[colors]`, and not part of the required `theme_tokens!` list: the 22 required tokens and
   `Theme::TOKEN_NAMES` stay as they were, old theme files keep working.
6. **No request debounce.** The engine replaces queued requests and cancels the running one,
   and `update` plus the hand-off costs microseconds (see Measurements), so a debounce would
   only add latency. Revisit if real-world hold-`j` through huge directories shows disk churn.
7. **No "loading…" text in the pane.** A cache hit arrives in under a millisecond, so a
   placeholder would flash on every cursor move. The header (from the list entry) is shown
   immediately and the body stays empty until the result arrives.
8. **Parent column uses the engine's directory preview** (dirs first, natural order, hidden
   per the toggle, capped at 500 entries) instead of re-using the list's sort setting and
   without git glyphs/child counts. "Same renderer as the list, dimmed" is implemented by
   sharing the entry model, icon map and style rules (`dir_row`), not the list's virtualised
   row builder (which is tied to `DirView`, marks and git).
9. **`J`/`K` scroll half a page, `i` metadata uses the UI's own local-time formatting** (the
   engine formats UTC).
10. **Changed assertion in an existing test**: `nav::tests::a_superseded_navigation_never_commits`
    asserted `first.is_empty()` after `j`; a cursor move now (correctly) emits a preview
    request, so it asserts "no `ListDir` effect" instead.
11. The Normal hint line now ends with `‹w› preview ‹P› columns ‹i› info` after `quit`; they are
    the first entries dropped (shown as `…`) on narrow terminals. Snapshots of the main screen
    were regenerated for this. The full hint set is still P5's job.
12. The test `graphics_that_left_the_screen_ask_for_a_clear` raced with other rendering tests on
    the process-global image host (flaky); the decision is now the pure function
    `images::graphics_left` and the test no longer touches the global.

## VERIFY results

- **Image protocol in Windows Terminal**: not verifiable here (no interactive terminal).
  Logic: `Picker::from_query_stdio_with_options` writes a combined DA1 / cell-size / kitty /
  DSR query, waits for the DSR answer (max 250 ms), picks kitty > sixel > (iTerm2 by
  `TERM_PROGRAM`) > halfblocks. The user's WT is 1.24 (Sixel since 1.22) and does not speak the
  kitty or iTerm2 protocols, so the expected result is **Sixel** if WT's DA1 answer reaches the
  app through ConPTY, otherwise halfblocks. Default is `auto`; the first line of each log file
  shows the outcome (`image protocol detected=... took_ms=...`). If detection picks halfblocks
  in WT, set `[preview] image_protocol = "sixel"`. Run in a plain conhost window (hidden
  `Start-Process`) the query produced `halfblocks (cell 10x20 px)` in 0 ms and the app ran
  normally. Known library caveat: when a terminal never answers, the library's reader thread
  stays blocked on stdin and can swallow the first key press; `image_protocol = "halfblocks"`
  skips the query entirely.
- **Sixel clean-up**: Sixel pixels stay until overpainted, hence the clear-and-redraw in the
  event loop when the image area changes. Untested in a real terminal.
- **Halfblocks rendering**: solid-colour cells are drawn as a space with a background (the
  primitive encoder), photos use `▀`/`▄`; verified in tests.
- **`ThreadProtocol` stability**: `needs_resize` must be given the full pane area every frame
  (not the fitted rectangle) or the image is re-encoded every frame; found with a failing test
  and handled in `images::render_image` (resize decision on the full area, only the drawing
  position is centred).
- **Cloud placeholders** are never read (engine `Unavailable{CloudPlaceholder}`; the pane shows
  the reason and metadata). Only exercised with the engine's injected-attribute test and the
  `unavailable_*` snapshots, not a real OneDrive file.

## Theme `[syntax]` table (document with the theme format)

Optional table in a theme file with the keys `keyword string comment function type number
constant operator punctuation`, each a colour like the `[colors]` values. Unset keys derive from
existing tokens (keyword=accent, string=success, comment=fg_muted, function=dir, type=warning,
number=symlink, constant=git_untracked, operator/punctuation=fg_dim). A user theme inherits its
`base`'s explicit syntax colours. On a theme switch (P5) call
`EffectRunner::set_preview_palette(theme.syntax_palette())`; the event loop does this once at
start-up (`event_loop.rs`), and P5's switch handler is not in this base so it is the integrator's
one-line addition. P7: `preview::sync` compares the cursor path, so a tab switch re-requests the
preview with no extra code (unit-tested only for cursor changes; no tabs in this base).

## Measurements

Keypress to frame, `update()` + full render into a `TestBackend` of 160x48 with 1000 list
entries and a 38-line highlighted preview (`ks-ui` test `keypress_to_frame_stays_within_budget`,
200 presses after a warm-up press):

| Build | mean | p99 | max |
|---|---|---|---|
| release | 0.23 ms | 0.31 ms | 0.41 ms |
| debug | 2.3 ms | 2.8 ms | 3.0 ms (when run alone) |

Budget is 16 ms. Run: `cargo test -p ks-ui --release keypress -- --nocapture`. The test
asserts p99 < 16 ms in release and mean < 40 ms in debug (a parallel test run inflates debug
outliers).

Holding `j` through 60 files of 240 KB (`ks-app` test, real engine): 59 presses processed in
53 µs (release) / 248 µs (debug) in total, slowest single press 12 µs / 46 µs, because `update`
only hands a request to the engine; the engine skips superseded requests (fewer than 59 results
arrive) and only the last file is shown. Revisiting a file: result delivered 0.1 to 0.9 ms
after the request (`from_cache = true`). Highlighting cost itself is in `engine-preview.md`
(83 ms for the default 2,000 lines, release; off the UI thread).
