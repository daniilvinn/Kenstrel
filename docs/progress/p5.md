# P5: command palette, help, which-key, keymap config, themes

Branch `phase/p5` (base bf87255). Not committed. Gates (fmt, clippy -D warnings, test --workspace) clean.

## Done

- **Command registry** (`ks-core/src/command.rs`): `Category`, a `COMMANDS` table (category + description per action) and `info(action)`; id and title stay on `Action`. A test fails when an action has no row. Two new actions: `theme.switch` ("Switch theme") and `icons.switch` ("Switch icon set"); `config.reload` already existed. All three are palette-only (no default key).
- **Palette** (`ks-core/src/palette.rs`, `ks-ui/src/palette.rs`): `:` opens a centered rounded box (`╭─ Commands ─╮`, `›` input line with a counter, rule, results). Fuzzy matching with `nucleo-matcher` over titles (also falls back to the stable id such as `file.trash`, no highlight). Matched chars accent+bold, bindings right-aligned in `fg_muted`. Up/down, ctrl-n/ctrl-p, pageup/pagedown (all keymap contexts `palette`, rebindable), enter runs, esc closes. Recents first on an empty query and as tie-break on a query (session only). `Switch to tab` is expanded to 9 entries (`Switch to tab 3`, bound `3`). `Set bookmark` / `Jump to bookmark` arm their key prefix (`m`/`'`) and the next key completes them (status says "press a character"); with no such binding they explain it. Unimplemented actions report "<title> is not available yet" as before. `Switch theme` / `Switch icon set` open a second page of the same overlay (esc goes back one page first).
- **Help** (`?`; `ks-core/src/help.rs`, `ks-ui/src/help.rs`): generated from registry + live keymap, grouped by category, shows every command (unbound ones as `—`), j/k, ctrl-d/u, gg/G, pageup/down, home/end, `/` filter (typed text goes to the field, enter keeps the filter, esc clears, a second esc closes). Digit bindings collapse to `1-9`. Position `a-b / n` in the bottom border.
- **Which-key** (`ks-ui/src/which_key.rs`): boxed popup bottom-right of the list body, title is the pending prefix (`╭─ g ─╮`), shown after `ui.which_key_delay_ms` (timer/Msg existed since P0). Splits into columns when there are more entries than rows, works down to a 3-row body; below that it falls back to the old hint-line rendering. The hint line now keeps its normal hints while the popup is visible; palette and help get their own hints.
- **Keymap config**: default bindings added for the `palette` and `help` contexts. `apply_overrides` now also reports (a) a user binding that shadows other bindings (`g` removes `g g`...; `q q` removes `q`) and (b) unbinding something that is not bound; `""` unbinds like `"none"`. Plain same-key rebinding stays silent. Issues go to the status line (first + "+N more") and the log. `settings::build_keymap` is shared by start-up and reload.
- **docs/keymap.md** is generated by `ks-core/src/docs.rs`. Drift test `docs::tests::docs_keymap_md_is_up_to_date` (CRLF-tolerant); regenerate with `KESTREL_UPDATE_DOCS=1 cargo test -p ks-core docs` or `ks --dump-keymap > docs/keymap.md`; a CLI test checks the binary output equals the file.
- **Themes / config reload**: `Effect::ReloadConfig` and `Effect::SetTheme{name,announce}`; `ks-app/src/reload.rs` (`Reloader`) does the file work; `event_loop::run_with` (new; `run` still exists and delegates with `None`) performs these two effects itself because it owns the theme, and feeds `Msg::ConfigReloaded`, `Msg::ThemeApplied`, `Msg::ThemesAvailable`. `ThemeLoader::available()` lists built-ins then `%APPDATA%\kestrel\themes\*.toml`. A broken `config.toml` on reload keeps the running settings and shows the error; a broken theme keeps the old theme. Icon-set choice is applied immediately.
- Tests: update()-level tests for palette/help/text input/keymap overrides, ks-app event-loop tests (palette -> reload config, switch theme, broken theme, no reloader), Indexed256 render check, insta snapshots at 80x24 and 160x48 in ember and paper for palette (plain, query, theme page, empty), help (plain, scrolled, filtered) and which-key (`g`, `S`, `m`; plus 80x12), tiny-terminal no-panic tests.

## Deviations

1. **Theme/icon choice is session-only** (not written to config.toml), as allowed by the brief.
2. **Config/theme file reads run on `spawn_blocking`** (review fix; previously on the loop thread). `event_loop::dispatch` starts them and results come back through a private unbounded side channel (`Side::Msg` / `Side::Theme`, needed because `Msg` cannot carry a `Theme`); the loop adopts the loaded theme when it arrives. Start-up theme listing is also off-thread, so `state.themes` fills a few ms after the first frame.
3. **`event_loop::run_with` added** instead of a new field on `LoopOptions` so other tracks' `LoopOptions { .. }` literals keep compiling.
4. `Keymap` now derives `PartialEq, Eq` (needed so `Msg` stays `Eq`).
5. Which-key shows `any key` for `<char>` continuations (was `any`).
6. Palette sort entries are the existing four `sort.*` actions (no sort submenu entry), bookmarks use the prefix-arming described above.

## VERIFY results

- Truecolor vs 256: `ColorDepth::detect` was covered in P0; new test `indexed_256_colours_never_use_rgb` renders the palette with an Indexed256 theme and asserts no `Color::Rgb` anywhere.
- Wide characters at the left edge of a popup swallowed the border in a TestBackend dump (a double-width glyph spilling into the box); `popup::framed` now blanks such a cell first.
