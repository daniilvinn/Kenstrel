# Round-2 fixes B1: core, file ops, tabs, preview

## Done (all 5 items confirmed still applicable on eab9211)

1. **Bulk re-edit `n` leaked the kept edit file** (fileops/logic.rs). New helpers
   `discard_reedit_if_any` and `cancel_confirm`; esc and `n` both go through `cancel_confirm`
   (emits `BulkRenameDiscard` + "Bulk rename discarded"). Not inside `close_confirm` because
   `accept_confirm` closes first and then reopens the same file. A new bulk-plan result
   (Planned / Invalid) replacing an open BulkReedit confirm also discards it.
   Test: `n_on_the_bulk_reedit_dialog_discards_the_kept_file`.
2. **Two parked tabs on one directory** (tabs.rs). `on_parked_dir_changed` emits one
   `ListParked` per distinct path (first slot's ticket) and tags every matching slot's `bg`
   with that ticket; `parked_chunk` / `parked_finished` fan out to all slots with that `bg`
   ticket (`bg_slots`). Walk-cache diff is fed once. Each slot still bumps its own `list_gen`.
   Test: `two_parked_tabs_on_one_directory_are_both_refreshed_by_one_listing` (asserts exactly
   one ListParked, both slots non-stale and updated).
3. **Preview line-selection dead end** (preview_lines.rs). Took the verifiers' simplest fix:
   message is now "Claude is not running: esc, c to open it, then V again"; comment dropped.
   Selection is still kept (harmless). Existing test updated to the exact text.
4. **Synchronous `fs::metadata` in `update`** (nav.rs). `is_hidden_path` removed.
   `go_to_file` records `state.search.pending_unhide = Some(name)`; when the listing finishes
   (`finish_view`, or the refresh-supersedes-stream path) `apply_pending_unhide` asks
   `DirView::unhide_for(name)`, which turns hidden on only if the raw entry exists and
   `Entry::is_hidden()` (attribute or dotfile, already read by the lister) and puts the cursor on
   it, with the same status message. Cleared on any non-refresh navigation request.
   Test: `find_file_on_an_attribute_hidden_file_unhides_from_the_listing_without_a_stat`.
5. **Content-search hit beyond the preview cap** (preview.rs, ks-preview, ks-ui). True windowed
   read. `PreviewRequest.focus_line` / `Limits.focus_line` (1-based) asks the engine to centre a
   window on that line: `content::focus_window` counts `
` through the file (1 MB chunks,
   cancel-checked) to the start line (`focus - max_lines/2`), reads `max_bytes` from there and
   renders it with `TextPreview.first_line` = lines before the window. Only for plain UTF-8
   text (not markdown / UTF-16/32; those keep the head). ks-core: `TargetKey.focus` is the
   bucket centre (1,000-line buckets, so hits in one bucket share a window) when the head
   limits (`line+100 > max_lines` or `line*256 > max_bytes`) would not reach the hit;
   byte cap raised to at least 1 MB for the window. `follow_overlay_line` scrolls relative to
   `first_line`; the "beyond the preview limit" status remains only if the window still misses
   the hit (very long lines). ks-ui: gutter numbers and the hit mark use `first_line + index`,
   the footer says "showing lines a-b". The old widen-the-limits code is removed (no 100k line
   ceiling any more). Syntax highlighting starts mid-file without parser state (accepted).
   Tests: engine `focus_line_reads_a_window_around_a_deep_line`; core
   `a_grep_hit_beyond_the_preview_cap_requests_a_window_around_it`,
   `a_window_preview_numbers_lines_from_its_offset_and_scrolls_to_the_hit`,
   `a_grep_hit_the_preview_still_cannot_reach_says_so`; ui
   `a_window_preview_numbers_its_gutter_from_the_offset`.

## Reviewer findings pass (verdicts)

- Window bucket vs small `preview.max_lines` (2 findings): fixed. `focus_bucket` = clamp(max_lines/2, 2, 1000), so a hit is always inside the window. Test `a_small_preview_limit_keeps_every_hit_inside_the_window`.
- `Msg::Interrupt` leaked the kept edit file: fixed (discards). Test `interrupt_over_the_bulk_reedit_dialog_discards_the_kept_file`.
- `request_quit` discards before quit is confirmed: rejected. The quit confirm replaces the BulkReedit dialog (single confirm slot), so without discarding its file would leak if the user declines; the status reports it. Keeping the rename dialog while asking to quit would need a second confirm slot (out of scope).
- Windowed read only for plain UTF-8 non-markdown: deferred (see Open issues); markdown rendering is block-structured and needs parser state from the file start.
- Full sequential scan to the window start: deferred; off the UI thread and cancellable, no measurement taken (no benchmark corpus generated). A line index/cache is the follow-up.
- `pending_unhide` stale after failed listing / tab switch (2 findings): fixed. Cleared in `navigation_failed` and `prepare_to_leave`. Tests `a_failed_visit_clears_the_pending_unhide`, `leaving_the_tab_clears_the_pending_unhide`.
- Spurious discard when a new plan reuses the same edit file: fixed (`discard_reedit_except` keeps the file when the new retry points at it). Test `a_retry_reusing_the_same_edit_file_does_not_discard_it`.
- Windowed preview snapshot and same-bucket no-refire: fixed. Snapshots `grep_window_preview_{ember,paper}_160x48` (the overlay preview only exists on wide terminals, as for the other overlay-preview snapshots); test `moving_between_hits_in_one_window_bucket_requests_nothing_new`.
- Delete / Claude preflight discard untested: fixed. Tests `asking_to_delete_over_the_bulk_reedit_dialog_discards_the_kept_file`, `a_failed_preflight_dialog_discards_a_kept_bulk_rename_file`.
