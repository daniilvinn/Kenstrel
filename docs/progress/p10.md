# P10: Claude Code integration wiring (branch `phase/p10`, based on 886b106)

Wires `ks-claude` into the app per PLAN section 10: 10a (WT split), 10b (embedded pane), 10c
(mentions), 10d (IPC + MCP + `ks mcp`/`ks hook`), 10e (hooks to the `◆` marker, changes view,
activity feed). 10f (headless actions) is not built, by decision. `docs/progress/claude-wiring-ref.patch`
was used as a reference only; the wiring is a rewrite against the P1 code (no marks/cursor/list
stand-ins any more, IPC handled through `Msg`/`Effect`).

## Done

### Keys and commands (all are actions, so they show up in the palette once P5 lands)

| Keys | Action id | Title |
|---|---|---|
| `c` | `claude.open` | Open Claude (preflight, then the embedded pane; focuses it if already running) |
| `g r` | `claude.resume` | Resume last Claude session (`claude --resume <id>`) |
| `g w` | `claude.split` | Open Claude in Windows Terminal split (10a) |
| `C` | `claude.send_marked` | Send marked files (or the cursor file) as `@` mentions, focusing the pane |
| `ctrl-\` (normal and claude contexts; `[claude] focus_key`) | `claude.focus` | Toggle focus between explorer and Claude |
| `alt-=` / `alt--` (normal and claude) | `claude.grow` / `claude.shrink` | Resize the pane by 5 points (15..85 %) |
| `g p` | `claude.position` | Move the pane bottom / right |
| `g X` | `claude.close` | Close the pane (kills the process) |
| `shift-pageup` / `shift-pagedown` (claude) | `claude.scroll_up` / `claude.scroll_down` | Scroll the pane history |
| `g a` | `claude.changes` | Claude changes view (`j k enter X esc`) |
| `X` in the changes view | `claude.changes_clear` | Clear Claude changes |
| `y` in the billing dialog | `claude.proceed` | Proceed with API billing anyway |

Decision, 10a key: the WT split is `g w` ("window") plus the palette; `c` is the embedded pane.
`g x` would have been natural for close but the existing test `non_matching_second_key...` uses
`g x` as its "unbound" probe, so close is `g X`.

### ks-core (`claude.rs`, new; hub files only got additive arms)
- `ClaudeState` in `AppState.claude`, `Msg::Claude*`/`Msg::Paste`, `Effect::Claude*`/`SetBracketedPaste`,
  actions, keymap context `claude_changes` + `Overlay::ClaudeChanges`, `[claude]` config
  (`binary`, `strip_env`, `pane_position`, `pane_percent`, `focus_key`), `DirView::reveal_now`,
  `nav::reveal`.
- Preflight flow as pure `update` logic: `c` -> `Effect::ClaudePreflight` -> `Msg::ClaudePreflight` ->
  `Ok`: launch; `BillingWarning`: dialog with the exact text `Claude would bill your API key; aborting`
  and proceed ONLY on `y` (enter does nothing, esc aborts, nothing launches); `NotLoggedIn`: tells the
  user to run `claude` and `/login`; `NotInstalled`: install instructions; `Failed`: info dialog. The
  WT split goes through the same preflight (engine TODO from engine-claude.md closed).
- Focus = `Overlay::Claude` on top of the overlay stack. In that context only `claude.*` bindings are
  intercepted; every other key (esc, ctrl-c, shift-tab, q...) becomes `Effect::ClaudeKey(chord)` in
  `update` itself (tested), never reaching the explorer keymap.
- Layout in its own function, `claude::split_body(Area, position, percent) -> BodySplit`
  (bottom: min 5 rows pane / 4 list; right: min 40 cols pane / 30 list; smaller terminals: the pane
  covers the body). `AppState::viewport_height()` uses the list share, so scrolling stays right.
  PTY size = `pane_inner_size(state)`; `Effect::ClaudeResize` is emitted whenever it changes (resize,
  grow/shrink, position toggle, start).
- IPC handled as messages: `Msg::ClaudeIpc{id, request}`; `update` answers `GetSelection` (marked in
  list order, cursor file, cwd) and `HookEvent` itself (`Effect::ClaudeIpcReply`), and hands
  `ListDir`/`SearchFiles`/`SearchContents`/`Reveal` to `Effect::ClaudeIpcWork` with an `IpcContext`
  (project root, hidden/gitignore toggles). A verified `Reveal` returns as `Msg::ClaudeReveal` and
  navigates (in place when the parent is the displayed directory, else by visiting the parent with
  the cursor revealed).
- 10e: `ChangeLog` (normalised, case-folded keys; per-file tool + sequence), `activity_line`.
- 10c: `Msg::ClaudeSendPaths(Vec<PathBuf>)` and `Msg::ClaudeSendRange{path,start,end}` (entry points for
  P2 visual line ranges and P4 search hits; `@path#La-b`), both only act while the pane runs.

### ks-ui (`claude.rs`, new)
- `split_body(body, state)` (called from `render` before the list), pane with a rounded top border:
  ` Claude ` + `‹ctrl-\› focus` hint when unfocused (key looked up in the keymap), latest edit
  (`◆ Edit src/a.rs`) right-aligned in the border; focused border uses `border_focus`; screen cells
  drawn with inverse handled; hardware cursor only when focused; "Starting Claude…" placeholder.
- Dialogs (billing, install, login, failure) and the changes view as centered rounded overlays.
- `◆` (file) / `◇` (directory with an edited file below) after the name in the list row, accent
  coloured, `*` / `+` with the ascii icon set; the name column shrinks by two cells only for such rows.
- Hints for the `claude` and `claude_changes` contexts.

### ks-app
- `claude.rs` `ClaudeHost`, owned by `EffectRunner` (`with_claude(options)`): performs the effects;
  engine events become `Msg`s through a forwarder task; snapshots rate-limited to ~60/s (engine
  coalesces); keys, pastes, mentions, resize and scroll go through one ordered writer thread per pane;
  launch (session store, generated `--mcp-config`/`--settings`, `KESTREL_IPC`, ConPTY spawn) runs on
  the blocking pool; IPC server starts lazily at the first launch; launch dir is removed and stale
  ones (older than 24 h) swept; shutdown kills the pane. `ClaudeClose{generation}` also kills a pane
  that was still starting.
- `ipc_work.rs`: `ListDir` via `ks_fs::list_dir`, `SearchFiles` via `ks_search::FinderSession`
  (headless, walk cache shared across requests, 8 s budget, limit), `SearchContents` via
  `ks_search::spawn_search` (limit via `max_matches`, 20 s budget), `Reveal` existence check; all
  poll the reply's cancellation token.
- `ks mcp` and `ks hook` hidden subcommands (`args_conflicts_with_subcommands`: a directory literally
  named `mcp` must be written `./mcp`). `ks hook` prints nothing and always exits 0.
- Bracketed paste is enabled only while the pane has focus (`Effect::SetBracketedPaste`), `Event::Paste`
  becomes `Msg::Paste`; restored by `terminal::restore`. Raw `0x1c` is accepted as ctrl-\.
- `[claude] focus_key` rebinding in `settings.rs`; `AppPaths::state_dir()`; sessions in
  `<state>/claude-sessions.json`.

## Deviations (with reasons)
1. Billing confirmation needs `y`, not enter (PLAN says "explicit confirmation"); implemented with
   its own action `claude.proceed` bound in the `confirm` context.
2. The dialogs reuse `Overlay::Confirm` with `ClaudeState::dialog` because the generic confirm
   belongs to P6. The Claude hook in `run_action` only acts while `claude.dialog` is set.
3. (Superseded in the second pass, see below.) The WT split now carries MCP and hooks.
4. ks-search is a path dependency of ks-app (`ks-search = { path = "../ks-search" }`), not a
   workspace dependency, to keep the root `Cargo.toml` untouched (P3/P4 may add the workspace entry).
5. IPC `ListDir` has no `truncated` flag (protocol is the engine's); it caps at 2000 entries.
6. Default colours of the embedded screen map to the theme `fg`/`bg`, not the terminal defaults.
7. `Msg::Paste` is new in the shared enum; other text inputs never see it because bracketed paste is
   off unless the pane has focus.

## Third pass (review findings)

Fixed:
- **Paste on Windows.** crossterm 0.29's Windows reader never yields `Event::Paste` (only its unix
  parser does), so bracketed paste is not enabled on Windows any more (`set_bracketed_paste` is a
  no-op there; the markers would arrive as raw `Esc [ 2 0 0 ~` keys). Instead the event loop turns a
  run of 4 or more plain text keys (chars, enter, tab) that are all ready at once, while the pane has
  focus, into one `Msg::Paste` (`input::coalesce_burst`; enter becomes a newline), so a multi-line paste
  no longer submits partial prompts. Shorter runs stay ordinary keys. Unit-tested; not verified in a
  real console (see below). On other platforms real `Event::Paste` is used.
- **Session key = project root.** The runner keys the session store by the enclosing git repository
  (`project_root`, a `.git` dir/file walking up), else the launch directory; `g r` after `cd`-ing into a
  subdirectory resumes the repo's session. A plain `c` still stores a fresh id (the latest session is the
  one `g r` resumes; intended). The pane's own cwd is still the directory it was started in.
- **Frozen pane.** `on_started` asks for a fresh snapshot (`Effect::ClaudeScroll{0}`) because output
  that landed before the pane was registered was dropped while the coalescing flag stayed set.
- **PTY size drift.** The launch size is remembered in `claude.pty`; `on_started` compares it with the
  current layout and sends `ClaudeResize` if the window or split changed during start-up.
- **Dead-on-arrival pane** is no longer kept in the host (`has_exited()` check after spawning).
- **FPS cap** no longer sleeps in the forwarder: an early `PaneUpdated` is remembered and served by a
  timer branch of the `select!`, so IPC replies, preflight and exit events are never delayed and
  queued updates collapse into one snapshot.
- **Stale walk cache for `search_files`.** The cache is cleared on every hook event and when it is more
  than 5 s old at the time of a search (changes by the user or other tools).
- **IPC budgets.** Content search budget 12 s (below the 15 s reply timeout, so partial hits are returned).
  `list_dir` now scans up to 50k entries, sorts, and when it cuts to 2000 appends a visible
  "... listing truncated: showing 2000 of N entries" entry (the protocol has no flag).
- **Diff process storm.** `ClaudeDiff` requests are debounced (60 ms; only the newest runs), git is not
  started once superseded, and git output is read at most 512 KiB (then killed).
- **WT split launch dir.** Not deleted at shutdown once a split was launched (the split still uses
  `--mcp-config`/`--settings`); the next launch's sweep removes it after 24 h. Open: the sweep does not
  check whether the owning pid is alive.
- **Dialog footer clipping.** The key hint owns the last row of the dialog; the body is clipped instead.
  Test on an 80x10 / 80x8 terminal.
- **`g r` while running** says "already running; close it (g X) to resume another session".
- Tests added: burst coalescing, `on_started` refresh/resize, resume-while-running, `y` in Confirm
  maps once and other confirms ignore it, project root, `list_dir` truncation, `--resume <id>` through
  the fake binary (new `ClaudeOptions::projects_dir` so the test can place a transcript),
  `pane_focused_with_activity_*` snapshots (80x24, 160x48, both themes, long path shows truncation).

Rejected / kept by design:
- **`y` in the Confirm context** stays: a dedicated `Overlay` variant touches the same shared enums and
  P6's merge either way. Mitigation: a test pins that `y` is bound once in Confirm and a non-Claude
  Confirm ignores `claude.proceed`. At integration, if P6 binds `y` to its accept, remove the Confirm
  binding and route `y` through `claude::handle_action` first.
- **Top-only pane border** is deliberate (a boxed border would cost 2 more rows/columns of PTY space);
  recorded here as a deviation from PLAN 4's rounded borders on overlays (the dialogs/changes view are rounded).
- **ks-search as a path dependency** of ks-app: unchanged, to keep the root `Cargo.toml` and `Cargo.lock`
  churn out of this track; the integrator must dedupe it with P3/P4's entry.

Deferred (Open issues):
- Quitting Kestrel while Claude runs kills the session without asking; needs P6's generic confirm.
- The sweep of stale `kestrel-<pid>` launch dirs should check pid liveness (engine change).
- Paste burst detection and ctrl-\ decoding are untested in a real Windows console; the heuristic could
  mis-detect type-ahead of 4+ keys queued during a stall as a paste (text arrives intact, an Enter
  inside it is a newline rather than a submit).
- `viewport_height()` (state.rs) subtracts the bottom pane through `claude::list_height`, and `update`
  calls `claude::sync_layout` on `Msg::Resize`. When P2 changes the body split or P7 introduces `TabState`,
  keep that deduction (list height = body height minus the pane rows) and the `render.rs` `split_body`
  call; these three spots (`render.rs`, `viewport_height`, `Msg::Resize`) are the merge-conflict sites.
- Remaining from earlier passes: 10c range senders (need P2/P4), sharing P3's `WalkCache`, tab-aware `◆`,
  manual checks listed above.
