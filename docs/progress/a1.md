# A1: audit fixes, file operations, foreground, event loop

Base 2208fef (branch audit/a1). Findings: `audit-A.txt` (10 findings, 8 distinct defects: the
two results-list findings and the two resize findings are duplicates).

## Done (per finding)

All findings still reproduced on the base; none were already fixed.

1. Failed overwrite leaves the old destination parked (`ks-fs/src/ops/transfer.rs`).
   The `Ok(false)` arm now removes any partial result at `dst` and renames the parked item
   back (all-or-nothing). If the new copy is complete and only deleting a move's source
   failed (`copy_complete`), the replacement stays and the backup is dropped. If the restore
   rename itself fails the error names the parked path. Test:
   `failed_overwrite_restores_the_previous_destination` (Windows: source held open without
   delete sharing so the rename fails).
2. Cross-volume move dropped ADS/attributes/creation time. New
   `ks_fs::platform::copy_file_ex` (`CopyFileExW`, `COPY_FILE_FAIL_IF_EXISTS`, progress
   callback that feeds `add_bytes` and cancels via the job token; verbatim `\\?\` paths so deep
   trees still work). `copy_file_inner` uses it on Windows (portable read/write loop kept for
   other hosts). CopyFileExW does not carry the creation time, so it is set afterwards
   (`FileTimesExt::set_created`, read-only temp handled). The source is still only deleted
   when the copy produced no errors (existing `errors_before` check). Tests:
   `copy_preserves_alternate_streams_and_creation_time`, `copy_file_ex_reports_progress_and_can_cancel`.
3. Conflict dialog stole keystrokes (`ks-core/src/fileops`). `ConflictDialog.armed`: a dialog
   opens disarmed; every key (and enter/esc) is swallowed while disarmed and re-starts a
   600 ms `TimerKind::ConflictArm` timer, so it arms only after a quiet moment (no key is ever
   acted on if it arrived before the dialog was usable). The next queued dialog gets its own
   grace period. Overwrite is now shift-`O` only; plain `o` is inert. UI: choices drawn muted
   while disarmed, label `O overwrite`. README updated. Tests:
   `a_fresh_conflict_dialog_swallows_keys_typed_before_it_appeared`, `overwrite_needs_shift_o`,
   disarmed snapshots (80x24/160x48, both themes), existing tests adapted (`show_conflict`
   helper, headless tests wait for `armed`).
4. Finishing a move cleared a newer cut register. `finish_job` removes from the register only
   the paths the job moved (`done.removed`); empty register becomes `None`. Test
   `finishing_a_move_keeps_a_newer_cut`.
5. + 6. File-op completion / editor return replaced a results list. Guard in
   `nav::can_refresh` (`view.label.is_none()`), which covers `refresh_after` and
   `refresh_if_idle` (editor return). Test
   `file_op_completion_does_not_relist_over_a_results_list`.
7. + 8. Resize during a foreground program lost. `run_foreground` now returns messages: after
   `terminal.clear()` it reads `terminal.size()` and queues `Msg::Resize` ahead of
   `ForegroundDone` when it differs from `state.size`. Tests:
   `a_resize_during_a_foreground_program_is_resynced`,
   `the_state_size_follows_the_terminal_after_a_foreground_program`.
9. Worker-thread panic printed over the TUI. `install_panic_hook` calls the previous (default)
   hook only for UI-thread panics, after cleanup; worker panics go to the log only.
   `tests/panic_hook.rs` now installs a recording stand-in for the default hook and asserts
   it runs for the UI thread and not for a worker.
10. Error exits skipped flush/shutdown. The loop uses `break Err(..)` instead of `return`;
    the pending-writes flush, `runner.shutdown()` and `finish_state_writes` run on every exit.
    Test `error_exits_still_flush_state` (bookmark + visit saved although the input stream
    fails).

Trash undo test: `trash_undo` un-ignored (restores by original path; every step waits for job
completion). Passed 6/6 alone; the f3 failures came from a ~300-item bin and load. See VERIFY.

## Deviations

- Overwrite key changed from `o` to `O` (shift). The spec asked for an unambiguous key.
- Hub edits (additive): `TimerKind::ConflictArm` (msg.rs), one match arm in `update.rs`, a
  `arm_gen` field on `FileOps`, two fields' worth on `ConflictDialog` (`armed`), `nav::can_refresh`.
- `run_foreground` now returns `Vec<Msg>` (private fn).
- Results list after a file op: rows the job removed are pruned in place (`DirView::remove_names`,
  called from `refresh_after`); the list is never re-listed. Test
  `file_op_completion_prunes_removed_rows_from_a_results_list`. Renamed/moved rows (Move, Rename, BulkRename; removed and created are index-paired) are renamed in place via `DirView::rename_names` when the target is below the cwd; test `file_op_completion_renames_rows_in_a_results_list`.

## Review round 2 verdicts

- manual-test `o` overwrite: fixed (now shift-O).
- Disarm gate is a timer, not tied to render: deferred. The 600 ms quiet window is far longer than a frame and every swallowed key restarts it; render-coupled arming would need a draw-ack message. Esc/enter/ctrl-c are deliberately swallowed while disarmed (documented by a test).
- copy_file_ex canonicalize resolving links: fixed (only the parent is canonicalized; transfer.rs handles symlinks before the copy path anyway).
- Cut register stale after overwrite/merge move: fixed. New `JobReport.consumed_sources` (ks-fs) / `JobDone.consumed_sources` (ks-core), recorded for every successful move including replaced and fully merged sources; finish_job consumes the register from `removed` plus `consumed_sources`. Tests in ks-fs ops_transfer and ks-core logic tests. Integration note: other tracks constructing `JobDone`/`JobReport` need the new field.
- CopyFileExW without ALLOW_DECRYPTED_DESTINATION: fixed (flag added).
- Results-list branch of refresh_after skips cursor/reveal/git: deferred (polish; a results list has no created-row reveal semantics yet).
- No test for cancelled cross-volume move: added `cancelled_cross_volume_move_keeps_the_source` (skips on single-volume machines).
- Disarmed ctrl-c / per-key timer restart tests: added.
- Queued dialog arming tests: added.
- Over-long doc line in terminal.rs: fixed.
- Hub merge friction: acknowledged, no action.
