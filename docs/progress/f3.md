## Done

1. **Cut entries dimmed + flagged** (`ks-ui/src/list.rs`). Entries whose path is in the cut register (parent == cwd) get the
   `×` glyph in the mark column and a dimmed name/icon (muted colour + DIM). A marked entry keeps `●` (mark wins the glyph, still
   dimmed). A yank (copy) dims nothing. Snapshots `list_cut_*` (both themes, 80x24 and 160x48) plus a text assertion.
2. **`O` open-with honours marks and reads the registry.**
   - `Effect::ListOpenHandlers { paths }`, `Effect::OpenWith { paths, handler }`, `Msg::OpenHandlers { paths, names }` (were a single
     `path`; **shape change**, see integration notes). `O` uses marked entries or the cursor entry (cap `MAX_LAUNCH`), the menu is titled
     `Open N items with`, marks are consumed on choosing, the handler is launched once per path.
   - New `ks-fs/src/launch/registry.rs`: reads `HKCU\...\Explorer\FileExts\.ext\OpenWithList` (MRUList order) and `OpenWithProgids`,
     `HKCR\.ext\OpenWithList` and `OpenWithProgids`. Programs resolve through `HKCR\Applications\<exe>\shell\open\command`, then
     `App Paths` (HKCU/HKLM), then `PATH`; ProgIds through `HKCR\<progid>\shell\open\command`. Labels: plain-text `FriendlyAppName`
     (resource refs `@{...}` are rejected) else the capitalised exe stem. Commands are converted to `{file}` templates (`%1 %L %l %0`
     replaced, `%2..%9 %*` dropped, `%VAR%` expanded). Deduplicated by label and by exe file name; the old fixed list (Notepad, VS Code,
     Explorer reveal, Choose another app) is appended after the registry entries. `open_with_handlers_for(Option<&Path>)` is called from the
     runner inside `spawn_blocking` (off the UI thread). Uses the safe `winreg` crate, no new `unsafe`.
   - Tests: parsing helpers (command to template, env expansion, MRU order, labels, dedup), ignored real-registry test
     `launch::registry::tests::txt_has_registered_handlers` (run with `--include-ignored`; on this machine it returned Notepad, Cursor, ...),
     core test `open_with_acts_on_every_mark`.
3. **Bulk rename re-edit.** `BulkPlanResult::Invalid { problems, retry: Option<BulkRetry> }`. On an invalid plan the temp file is kept; the
   overlay is a Confirm `Bulk rename: N problems found` with the note "Your edits are kept: enter reopens the file, esc discards it",
   accept label `edit again`. Enter emits `Effect::BulkRenameEdit { dir, names, reuse: Some(file) }` (reopens the same file, with the user's
   edits); esc emits new `Effect::BulkRenameDiscard { file }` and the status `Bulk rename discarded`. A valid plan, "No names changed", and
   editor failures still remove the file. Tests: core unit test, snapshot `confirm_bulk_invalid_*`, two headless integration tests with a fake
   editor script (`invalid_bulk_rename_is_reopened_with_the_file_kept`, `abandoning_an_invalid_bulk_rename_removes_the_edit_file`; Windows only like the
   existing bulk tests).
4. **Stale launch-dir sweep.** `ks_fs::pid_alive(pid)` (Win32 `OpenProcess` + `GetExitCodeProcess`, access denied counts as alive; Linux:
   `/proc/<pid>`; other Unix: assumed alive). `ks_claude::sweep_stale_launch_dirs(base, own_pid, max_age, pid_alive)` now only considers
   `kestrel-<pid>` dirs whose pid is **not alive** (and still only dirs containing nothing but `mcp.json`/`settings.json`); the age is now a 60 s
   safety margin (was 24 h, the only criterion). `ks-app` passes `ks_fs::pid_alive`. Tests: sweep test (alive pid keeps its dir however old) and
   a platform test (own pid alive, exited child dead).
5. **Error/warning logging.** `update::set_status` (the single chokepoint of every status toast, including `Msg::Notify`) logs `Level::Error`
   with `tracing::error!` and `Level::Warning` with `tracing::warn!` (`ks-core` gained the `tracing` dependency, already in the workspace).
   Additionally promoted from `debug!` to `warn!`: listing failure (`ks-app/effects.rs`), temp-file removal failure, send/paste to Claude failures,
   file-op item errors (`ks-fs/ops/runner.rs`), watcher errors / cannot watch parent, pty resize failure, hook forward failure. Per-file noise
   (grep/walk/preview IO errors, git not found) stays at `debug!` on purpose. No dedicated test (needs a tracing subscriber capture).
6. **Help / palette / which-key / hint line.**

     (bottom / right)` to `Move Claude pane`, `Resume last Claude session` to `Resume Claude session`. No truncation at 80x24 or 80x12; test

## Review follow-up (final pass)

Fixed:
- Help now has context sub headings (`in finder`, `in grep`, ...) via `HelpLine::Subheading` and a `group` field on `HelpLine::Entry`; test `contextual_commands_sit_under_context_subheadings`.
- Registry reading is split: portable `registry::collect` over a `RegistrySource` trait (real impl in the Windows module, fake in tests). New tests cover HKCU MRU / HKCR / ProgId merge and precedence, App Paths resolution, friendly names, unresolvable programs skipped, empty registry, and that the fixed fallback list remains (`open.rs`).
- Registry command arguments are env-expanded (`%ProgramFiles%` etc.).
- `O` on a mixed-extension selection offers only handlers every extension offers (`open_with_handlers_for_all` / `common_handlers`); the launch applies the chosen handler to each marked file.
- `set_status` warn/error logging is covered by a test (global capture subscriber, unique texts).
- A kept bulk-rename edit file that vanished is rewritten instead of handed to the editor (test `a_kept_edit_file_removed_meanwhile_is_written_afresh`).
- Hint-line logic (`NORMAL_HINTS`, `normal_priority`, `fit_by_priority`) moved from `render.rs` into `ks-ui/src/hints.rs`; the two hint tests stay in `render.rs` because they use its test helpers.
- `move_undo_and_trash_undo` split: `move_undo` runs always, `trash_undo` (real Recycle Bin) is `#[ignore]`d so the gate no longer depends on host bin state; run it with `--ignored`.

Rejected:
- "Cut glyph hidden when marked": `x` (and `y`) clear the selection (`yank` calls `clear_selection`), so freshly cut rows are not marked; the glyph is visible. Dimming also stays for the rare marked-after-cut row.
- "Hint line drops mark/hidden/drives at 80 columns": deliberate; `q ? :` must never be cut and the spec asked for `/ filter`, `ctrl-p find`, `ctrl-f search` when width allows. The priority table stays static (it still resolves the key labels from the user keymap).
- "`enter (prompt, filter +9)` cryptic": the column is width-limited; the full per-context list is in `docs/keymap.md`. Now that help has sub headings the abbreviation is only a pointer.

Deferred / accepted:
- The kept bulk-rename temp file leaks if the process is interrupted (ctrl-c) while the re-edit dialog is open; only esc discards it. Small file in %TEMP%; a `kestrel-bulk-rename-*` age sweep would be the fix.
- `own_pid_is_alive_and_an_exited_child_is_not` can in theory flake on pid reuse; probability is negligible.
- Linux: `cargo check --workspace --exclude ks-search --all-targets --target x86_64-unknown-linux-gnu` is clean, `ks-search --lib` is clean. `ks-search` test and bench targets cannot be compiled from Windows (criterion -> alloca needs a Linux C compiler); by grep its tests use no `ls`/`sleep`, and the Windows path tests are `cfg(windows)`.
