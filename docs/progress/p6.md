# P6: file operations wiring

Branch `phase/p6` (worktree `E:\dev\Kestrel-wt\p6`, based on 886b106). Wires `ks-fs` `ops/` and `launch/` into
`ks-core` (state, messages, effects, `update`), `ks-app` (effect runner, terminal suspend/resume) and `ks-ui`
(prompt, overlays, snapshots). `PROGRESS.md` untouched.

## Done

Everything is reachable from the keymap and exists as an `Action` (so the P5 palette lists it): no new actions were
needed, the P0 `Action` enum already had them all.

| Keys | Behaviour |
|---|---|
| `y` / `x` | Register = marked entries (visible rows only, list order) else the cursor entry. Marks are cleared. Toast `3 yanked` / `2 cut`, and a persistent `3 yanked` / `2 cut` segment in the prompt line. |
| `p` | Copy: job into cwd. Items whose source already lives in cwd go into a second job with `ConflictPolicy::KeepBoth` (`a (1).txt`), the rest ask on conflict. Cut: Move job, register is consumed; sources already in cwd are skipped ("Already in this directory"). |
| `d` | Recycle Bin, no modal; toast `Moved to Recycle Bin: x · u to undo`. |
| `D` | Generic Confirm overlay with typed confirm (`yes`, or the count for 2+ items, case-insensitive). Wrong text keeps the dialog open with a message; enter on nothing does not delete. |
| `u` | `JobManager::undo`; errors (`nothing to undo`, `Changed(..)`) go to the status line; the undo job's own result toast is prefixed `Undo:` and has no undo hint. |
| `r` | Prompt line prefilled with the name, cursor before the last extension (dirs, dotfiles and extensionless names: at the end). Name validation by the engine (`JobSpec::rename`), errors as `Cannot rename: ...`. |
| `R` | Marked entries, or every shown entry if nothing is marked (vidir style). Temp file, editor, plan, preview in the Confirm overlay (`old -> new`, 12 lines + "and N more"), enter runs the `BulkRename` job (one undo entry). Invalid plans (duplicates, collisions, ...) are listed in an info-only Confirm and cannot be applied. Unchanged: `No names changed`. |
| `a` | Prompt; trailing `/` or `\` = directory, nesting allowed (`parse_create_input`). After the job the cursor lands on the new item. |
| `Y` | Menu overlay: absolute / relative / name (hot keys `a r n`, or j/k + enter). `format_paths` + `SystemClipboard`. |
| `o`, enter on a file | `Effect::OpenDefault { path }` (cursor entry only, not all marks). |
| `O` | Runner lists `open_with_handlers()` (`Msg::OpenHandlers`), Menu overlay with hot keys `1`..`9`. |
| `e` | `Effect::OpenInEditor { path, line: None }`. |
| `!` | Prompt, then a pager overlay streaming stdout/stderr lines (stderr in the warning colour, 20 000 line cap, follow mode, `j k g G ctrl-d ctrl-u pgup pgdn`). `ctrl-c` kills the process tree (pager stays open, status `cancelled`); `esc`/`q` closes the pager and also kills a command that is still running. |
| `g j` | Jobs overlay: queued/running/awaiting/finished rows, newest first, progress bar, percentage, throughput, ETA; `j k g G` select, `x` cancel the selected job, `esc`/`q` close. `job.cancel` from the palette (no overlay open) cancels the newest running job. |

- **Progress in the prompt line** (right side, with the spinner): one job shows `⠹ Copying big.iso 42% · 118 MB/s · 0:12`;
  several show `⠹ 4 jobs 42%`; scanning shows the file count. The 10 Hz tick runs only while `state.jobs` is non-empty
  (P0 infrastructure; `state.jobs` now holds every queued/running/awaiting job).
- **Conflict overlay** (`Overlay::Conflict`, queue of dialogs): `o` overwrite, `s` skip, `r` rename (inline name prompt, cursor before the
  extension; enter confirms, esc goes back), `k` keep both, `a` toggles "apply to all remaining" (a checkbox in the dialog; ignored by the engine for
  rename), `c` cancels the job. **Decision:** `enter` = keep both (non-destructive default), `esc` = cancel the whole job (nothing further is
  touched; already copied files stay). Answers go back through `JobManager::resolve`. A job that finishes (e.g. cancelled from the Jobs overlay) drops
  its pending dialog. Several jobs can have dialogs queued; "N more waiting" is shown.
- **Terminal suspend/resume**: `Effect::RunForeground { id, spec }` is handled by the event loop (it owns the terminal) through the new
  `ks_app::foreground::Foreground` trait. `TerminalForeground` drops the crossterm `EventStream` (stops its reader thread, which would steal console input
  from the child), leaves the alternate screen + raw mode (`terminal::suspend`), runs the program with inherited stdio, re-enters
  (`terminal::resume`), recreates the stream, the loop calls `terminal.clear()` (full redraw) and delivers `Msg::ForegroundDone`. The panic hook stays
  armed (`ACTIVE` is not cleared). Without a host (tests) the effect is answered with an error.
- **Terminal vs GUI editors**: known list from the engine (`vim nvim vi hx helix nano micro kak ... emacs -nw`) plus the new config flag
  `[editor] terminal = "auto" | "always" | "never"` (`auto` = known list). Terminal editors go through `Msg::Foreground` / suspend. GUI editors
  (`code`, `notepad`, ...) are started with `spawn_detached` and never suspend. `[editor] open` (non-empty) stands in for `$VISUAL`. For `line: Some(n)` a
  non-default `[editor] open_at_line` is treated as a whole command line (`nvim +{line} {file}`), otherwise the engine's per-editor template is used.
- **Bulk rename with a GUI editor**: the runner blocks (off the UI thread, TUI untouched) until the editor process exits; for the VS Code family
  `--wait` is added automatically. If a GUI editor returns within 1.5 s without changing anything the user is told to use a blocking editor. A non-zero
  exit of a terminal editor (`:cq`) aborts the bulk rename (temp file removed).
- **After ops**: on `Job` completion the cwd is re-listed at once (`nav::refresh_if_idle`, which does not clobber a navigation in flight) and the cursor is
  revealed on the last created/renamed/pasted item in cwd (`view.set_reveal`). The watcher still refreshes afterwards.
- **Generic Confirm overlay + toast** are owned here as requested: `ConfirmDialog` (title, lines, optional typed token, danger style, optional action),
  toasts reuse the P0 status line (3 s, 8 s for errors).
- Shared effects with the exact requested shapes: `Effect::OpenDefault { path: PathBuf }`, `Effect::OpenInEditor { path: PathBuf, line: Option<u32> }`.
  `Enter`/`l` on a file now emits `OpenDefault` (the P1 "not available yet" message is gone).
- **Quit while jobs run**: `EffectRunner::shutdown` cancels all jobs and shell commands and waits up to 1.5 s (`wait_idle`) so job threads can
  delete their `.part` files before the process exits.

## Deviations (with reasons)

1. **Engine events are mirrored in `ks-core`** (`JobMsg`, `JobDone`, `ConflictInfo`, ...) instead of using the `ks-fs` types: `ks-fs` depends on `ks-core`, and `Msg`
   must be `Eq`. `ks-app/src/fileops.rs` maps them 1:1 (unit-tested).
2. **Name validation and typed-confirm tokens**: validation (`validate_name`, `parse_create_input`) runs in the runner (`Effect::Rename`/`Effect::Create`) because
   it lives in `ks-fs`; errors come back as an error toast. The `yes`/count token rule is duplicated in `ks-core` (`confirmation_token`, three lines).
3. **Prompt and dialogs use hard-wired keys for text and hot keys** (`o s r k a c` in the conflict dialog, `a r n` / `1..9` in menus, `y`/`n` in plain
   confirmations, all editing keys in prompts) via `fileops::intercept_key`; enter/esc/ctrl-c, scrolling and cancelling go through the keymap contexts
   (`conflict`, `menu`, `pager`, `jobs`, `confirm`, `prompt`) so they are rebindable. Adding an action per dialog key would have polluted the palette.
4. **Esc in the conflict dialog cancels the job** and enter keeps both (see above), not "esc = skip".
5. **Pager box leaves the header row and the prompt/hint rows visible** (height = terminal height - 3).
6. **Engine events go through an unbounded channel + forwarding task** rather than `blocking_send` in the sink: `JobManager::submit`/`cancel` call the sink on the
   caller's thread (which is inside the async runtime), where `blocking_send` would panic.
7. **Cut entries are not dimmed in the list** (would need an edit in `list.rs`, owned by the P2 layout work). The register count is shown in the prompt line instead.
8. `Msg::JobStarted` / `Msg::JobFinished` (P0 placeholders) are left in place and unused; `state.jobs` is driven by `Msg::Job`.
9. Existing tests that used `y` ("Copy is not available yet") now use `z` (frecency, not wired yet): `update.rs`, `event_loop.rs`. P7 will make `z` real; whoever
   merges needs another unimplemented action there.

## Review pass

Fixed (with tests):
- Ctrl-C meant for a foreground program no longer quits Kestrel: the interrupt listener ignores signals while `FOREGROUND_ACTIVE` (set by a guard around every foreground run) and keeps listening afterwards.
- Input typed while a terminal program exits is flushed after `resume` (`foreground.rs`), so it cannot replay into the list.
- Jobs overlay selection follows the row (index shifts on insert, adjusts on history trimming, clamped), so `x` cannot cancel another job.
- Quit (`q`, `Q`) with running jobs opens the generic Confirm (`ConfirmAction::Quit`); the process-level `Msg::Interrupt` still quits at once. The "spinner" event-loop test now accepts the confirm.
- A cut register is consumed when the move succeeds (`Done`, not undo), not at submit; failed or cancelled moves keep it.
- `o` / `e` refuse more than `MAX_LAUNCH` (8) items; `e` skips directories.
- The cursor reveal after a job is only set when the refresh is actually issued (`nav::can_refresh`).
- Undo jobs are recognised by their own `Generation(1)`; the shared `undo_jobs` set and its mutex are gone (no growth, no lock on the engine thread).
- Confirm dialog on short terminals counts the lines it cannot draw into "and N more".
- Clipboard is injectable (`EffectRunner::set_clipboard`); runner tests cover Absolute / Relative / Name formats, the plural toast and the error toast.
- New tests: keep-both through `enter` + copy undo, shutdown cancelling a big copy, editor terminal/GUI table, `[editor] terminal` invalid value, printable keys never reach the keymap from the shell, rename and conflict-rename inputs.

Rejected / already covered: "keep both (`k`) not exercised through the runner" (it is, in `yank_paste_cut_paste_and_the_conflict_dialog`; only `enter` and copy-undo were missing and are now added); "Esc cancels the whole job" (documented deviation, Esc first leaves the inline rename; kept so Esc never picks a destructive default); "register keeps stale paths" (revalidating needs fs access in core; failures surface per item at job time); `effects.is_empty()` in `paste` (the vec is local to one `update` call and nothing precedes the paste handler).
