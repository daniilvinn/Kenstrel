# Round-2 fixes B3 (Claude session, git hardening, hook quoting, static CRT, watcher)

## Done (all six items confirmed still applicable on eab9211)

1. **Session keying (bug major)** - `ks-claude/src/session.rs`: every stored id now remembers the
   directory it was created in (extra map keys `<root>\u{1}cwd` and `<root>\u{1}confirmed\u{1}cwd`;
   old files load unchanged, entries without a cwd use the requested cwd as before).
   New `SessionStore::launch_for(root, cwd, resume) -> SessionLaunch { mode, cwd }`: the transcript
   is looked up in the stored cwd's project dir and the returned cwd is where `claude` must be
   started (new ids are bound to the requesting cwd; a never-used id is re-bound on reuse).
   `mode_for_in` is kept as a wrapper. `forget_launched_in(root, launch_cwd)` only forgets an id
   that was created in that cwd. `ks-app/src/claude.rs` `launch()` uses `launch_for`, spawns the
   pane in the returned cwd, and `LaunchInfo.cwd` feeds `forget_launched_in`.
   Tests: `resume_from_a_subdirectory_launches_where_the_session_was_created` (root then src, with
   and without src's own project dir, `c` from src), `a_failed_resume_from_another_directory_keeps_the_stored_id`.
2. **git hardening (bug major)** - `ks_fs::git::git_command(dir)` (public) is the one hardened
   builder (`--no-optional-locks`, `core.fsmonitor=false`, `core.untrackedCache=false`,
   `protocol.ext.allow=never`, `GIT_OPTIONAL_LOCKS=0`, `GIT_TERMINAL_PROMPT=0`, `GCM_INTERACTIVE=never`,
   CREATE_NO_WINDOW). `run_git` in ks-app uses it (keeps the byte cap + kill). Both `git diff`
   calls gained `--no-textconv`. Only other non-test `git` spawns are in ks-fs `git.rs` (already
   using the builder). Test `booby_trapped_repo_never_executes_hooks_on_diff` (fsmonitor + textconv
   markers, with a control run proving the hooks fire).
3. **Hook quoting (bug minor)** - `ks-claude/src/gen.rs`: the shell-string hook is now
   `'<path>' hook` with `'` written `'\''` (single quotes disable all expansion). Test with
   `C:/T$x/`k`/$(calc) it's/ks.exe`, plus a round trip through `sh -c printf` when `sh` exists.
   Exec style left unchanged (still not default: older Claude Code ignores `args`).
4. **Static CRT (gap minor)** - `.cargo/config.toml` with `+crt-static` for
   `x86_64-pc-windows-msvc`; `ci.yml` workflow-level `RUSTFLAGS` (which would override the config)
   moved to a job-level env that adds `-C target-feature=+crt-static` on Windows only, and a
   Windows CI step fails if the release exe mentions vcruntime/msvcp/ucrtbase/api-ms-win-crt DLLs.
   `release.yml` sets no RUSTFLAGS, so the config applies there.
5. **Long-path watch (gap minor)** - `ks-fs/src/watcher.rs`: watch calls (dir and parent) use
   `ops::paths::verbatim` for paths >= 240 bytes on Windows; the watched dir and every event path
   are compared with the `\\?\` / `\\?\UNC\` prefix stripped (`plain`). Windows test with a
   > 300 char directory (`a_directory_beyond_max_path_can_be_watched`).
6. **Burst flake (flake major) + product bug** - the watcher is now trailing-edge: the debouncer
   handler only signals a coalescer thread, which calls `on_change` once after `QUIET` (50 ms)
   without a batch, after `MAX_DELAY` (1 s) of continuous activity, or at once on a watcher error.
   Drop sets a stop flag and closes the channel (no late callbacks). The test is split: exact,
   disk-independent tests of `coalesce` (`coalescing_a_burst_of_batches_gives_exactly_one_call`,
   cap, broken/stopped) using polling instead of timing, plus an integration test whose bound is
   the mechanism's real bound (`2 + burst/QUIET + burst/MAX_DELAY`).

Also fixed (not in my list, same Claude area): `claude_flow.rs` waited for `FAKE-CLAUDE-READY` but
then read the `ARG` lines printed after it, failing 3 of 4 runs here; it now waits for the last
line (`KEY=[]`).

## Deviations

  pane's cwd is the directory the conversation was begun in (not always the browsed directory).
  `docs/progress/p10.md` says the pane stays in the current directory; this is the exception
  for resumes (new sessions still start in the browsed directory).
- Notification latency after a change is about 100 ms debounce + tick + 50 ms quiet (was ~100 ms +
  tick).
- No `longPathAware` manifest added (optional per verifier notes).
