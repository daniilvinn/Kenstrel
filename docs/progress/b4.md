# b4: flaky tests and persistence robustness (round 2)

## Done
1. many_threads_writing_at_once_lose_no_bookmark (flake): the test now models a real instance (`store.load().bookmarks`, add key, write). Replaced by `concurrent_instances_lose_no_bookmark` (runs both interleavings: free-running and a `Barrier` after load) and a deterministic sequential test `a_later_instance_keeps_the_bookmarks_an_earlier_one_saved`. Threads use a 60 s lock wait so no fall-through happens.
2. atomic_write temp name (flake/product): `.{name}.{pid}.{seq}.tmp` with a process-wide AtomicU64, so a lock timeout can no longer turn into NotFound. `FileLock::acquire(path, wait)`: wait is now a `StateStore.lock_wait` field (default 8 s, was 3 s), STALE raised 10 s -> 30 s (must stay above the wait); `StateStore::with_lock_wait` is cfg(test). sync_all stays inside the lock before the rename. New test `atomic_writes_to_one_file_use_distinct_temp_names`.
3. palette_* / broken-theme event_loop tests (flake): no sleeps. `Reloader` has a cfg(test) `after_job` hook (`JobKind::{Reload,Theme}`) called as the last statement of each blocking job; tests install a hook that sends `Side::Msg(Interrupt)` after a Theme job (every scenario ends with one; a reload that changes the theme starts one), so quit is ordered after the results through the same FIFO channel. The theme list is seeded through `LoopOptions.startup` (`ThemesAvailable`). `settled()` and the timed ctrl-c are gone. `Side` is now `pub(crate)`. Product change: the loop draws once more before breaking on quit if `state.dirty` (the throttle could otherwise skip the last frame). The reload itself was already off the UI thread (spawn_blocking), nothing to move.
4. claude_flow fake-claude test (flake): waits for `prompt>` (printed after all ARG/IPC/KEY lines) before the first screen read and before the `--resume` read.
5. fileops bulk rename (flake): fake_editor is pure cmd (`for /f` + `move`), no PowerShell; it now appends to `<script>.paths` so `assert_edit_files_gone` is no longer vacuous, and that helper asserts the editor ran. flaky_editor's PowerShell calls replaced by `(echo a&echo b)> file`. The 500 ms settle before the discard check is now a poll. The optional plan_bulk remove_file retry was skipped (verifiers: optional).

6. (extra) ks-fs `launch::shell::tests::cancel_kills`: the only timing was `elapsed < 10 s` including PowerShell start-up; the sleep is now 120 s and the bound 60 s (cancel kill logic itself unchanged).
7. (extra) fileops shell test: the `settle_ms(300)` before ctrl-c is replaced by `until` the pager status is `Running`; `settle_ms` removed; elapsed bound 40 s.

## Follow-up (watcher flakes, claude_flow timeout)
- `a_watched_directory_reports_changes_until_watching_stops` and `parked_directories_are_watched_as_a_set` (ks-app effects.rs): root cause is a test race, not a debouncer bug. The watch is installed asynchronously after `WatchDir`/`WatchParked`; the fixed 300/400 ms sleep followed by a single write could land before the watch existed, so no event ever came and the 30 s wait expired. New helper `change_until` writes a fresh probe file every 250 ms until the expected message arrives (30 s overall), so the test no longer depends on setup timing. The sleeps before the positive checks are gone; the negative checks (after stop/park removal) are unchanged. 15/15 loop runs passed.
- claude_flow `pump_until` timeout raised 60 s -> 180 s (starvation under concurrent cargo loops; it already waits on specific content).
- Gates after this change: fmt, clippy -D warnings, `cargo test --workspace` all clean.

## Review findings (final pass)
- Negative watcher assertions (effects.rs): fixed for `parked_directories_are_watched_as_a_set` (write to the dropped dir, then a sentinel write to the still-watched dir; absence is checked only up to the sentinel event). Rejected for the single-dir stop test: no watched sentinel exists after `StopWatching`, so absence needs a quiet window; it only fails when an event is late, and the pre-stop drain is kept.
- cmd fake editor: kept `for /f` (no PowerShell) but added `eol=`, CRLF line endings via explicit join, and a comment on the plain-name limit (empty lines, `& % ^ !` unsupported). Leaked `.new` on failed move is harmless (tempdir, and `assert_edit_files_gone` checks the edit files).
- Draw-before-quit: new test `the_last_changes_are_drawn_before_quitting`; the quit draw now also clears `state.dirty`. Reload-test hang: failure message now says no theme job ran; the Theme-only hook stays (every scenario ends in a theme job).
- Persist: `temp_path` extracted, test `consecutive_temp_paths_differ` (platform independent); the literal newline is gone; new tests `a_held_lock_times_out_and_the_write_still_lands` (fall-through, no NotFound) and `a_stale_lock_is_removed`. `StateStore::write` runs only on the writer thread (and the exit flush), so the 8 s wait cannot stall the UI.
- Deferred: sweeping orphan `.*.tmp` files at start-up (low impact, state dir only; needs a start-up hook outside this track). The fall-through can still lose a merge after 8 s by design (best effort).
