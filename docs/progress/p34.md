# P3 + P4: in-directory filter, find file, content search (wiring)

Branch `phase/p34` (based on 886b106). Wires `ks-search` into core / ui / app. Not committed.
Gates: `cargo fmt --all`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace` clean.

## Done

**Filter (`/`, Filter mode)**
- `DirView` gained `filter` (query), parallel `highlights`, a separate `hidden` counter and `label`. Rows are the
  nucleo matches of the display names (`ks_search::filter_list`), best score first, recomputed on every keystroke
  (no debounce), on every streamed chunk and on every watcher refresh, so the filter survives refreshes.
- `enter` keeps the filter (chip `/foo` on the prompt line), `esc` clears it (cursor stays on its entry), a new
  query puts the cursor on the best match. `up/down/ctrl-n/ctrl-p/pageup/pagedown` work while typing; `j/k` etc.
  work after `enter`. A directory change builds a new `DirView`, so the filter is dropped (and filter mode left).
- Matched characters are accent + bold in the list (not drawn when the name had to be shortened with `…`).
  An empty result says `no entries match /q (esc clears the filter)`.

**Find file (`ctrl-p` / `f`)** — overlay per PLAN 4.3
- Centered rounded overlay, title `Find file · <scope> · <root>`, `›` input with block cursor, counter
  `1,234 / 58,910` plus spinner while walking (right of the input), ranked results with matched characters accent +
  bold, dim directory part, marks `●`, `▌` selection bar, footer with scope / hidden / ignored state and marks.
- `ctrl-r` cycles cwd → git root → home → drive, `alt-.` hidden, `alt-g` gitignored; each restarts the session under
  a new generation (the walk cache makes revisits instant). Scope and toggles are remembered for the next opening.
- Keys: `up/down/ctrl-n/ctrl-p`, `pageup/pagedown`, `tab` mark (and move down), `enter`, `ctrl-enter` / `ctrl-o` open
  with the default app (marked results, else the highlighted one; overlay stays open), `esc` / `ctrl-c` close.
  Text keys edit the query: plain chars, backspace, delete, left/right/home/end, `ctrl-u` clears.
- `enter` semantics: no marks → navigate to the file's directory with the cursor on it (new `nav::go_to_file`, a
  normal `Visit`, so history works). Marks all in one directory → navigate there, cursor on the first mark, **all
  marks applied** once the listing has loaded. Marks in several directories → a results list ("Find file: <query>").
- Worker: `ks-app/src/search.rs` `FinderWorker` owns the `FinderSession` on a thread, ticks it (~16 ms while walking
  or matching, sleeps on its command channel otherwise) and posts throttled `Msg::FinderResults` snapshots
  (query, root, counters, a 3-page window of results around the viewport). A snapshot is only sent once the matcher
  caught up with the latest query, so a snapshot labelled with a query always answers it. Core drops snapshots whose
  generation or query is not current.
- Walk cache (`Arc<WalkCache>` in the effect runner) is shared by all sessions of a run. Incremental refresh: when a
  watcher-triggered re-listing of the displayed directory completes, `nav` diffs old/new entries by name and emits
  `Effect::WalkCacheChanges(Vec<PathChange>)` → `cache.apply_changes` (on a blocking thread). Verified end to end
  (`the_walk_cache_follows_directory_changes`).
- Preview hook: wide terminals (≥ 100 cols) split the overlay; the right pane is a placeholder
  (`preview: wired by P2`). Integration points: `ks_ui::search::preview_rect(&state) -> Option<Rect>` and
  `ks_core::preview_target(&state) -> Option<PreviewTarget { path, line }>`.

**Content search (`ctrl-f` / `s`)**
- Two fields (query, glob; `tab` / `backtab` switch), chips `regex`, `word`, `smart-case`; `ctrl-r` regex,
  `ctrl-w` whole word (overlay-local actions `grep.regex`, `grep.word`), `ctrl-l` send to results list.
- 120 ms debounce through `TimerKind::GrepDebounce`. Every change bumps the search generation immediately and
  emits `Effect::GrepCancel` (late events of the old search are dropped); the timer fire clears the results and emits
  `Effect::GrepStart`. Engine events map 1:1 to `Msg::Grep(GrepEvent)`; the runner holds the `GrepHandle` (dropping
  cancels). An empty query clears results without searching. Query/glob/toggles are restored on reopen (and re-run).
- Results grouped by file (`path  N` header, ` 42│ text` lines, match ranges accent + bold, lines with a far match
  scroll so the match is visible), virtualized scrolling (only visible rows are built; headers are skipped by the
  selection), sorted by path when the search finishes (the highlighted hit stays highlighted). Footer: matches / files
  / searched / skipped cloud, denied, binary, large; `10,000+ matches: refine your search` when capped; engine errors
  (bad regex/glob) replace the footer.
- `enter` → `Effect::OpenInEditor { path, line: Some(n) }`.
- `ctrl-l` → `nav::show_results_list`: a real `DirView` of `cwd = search root` whose entry names are root-relative
  paths (so `cwd.join(name)` is the file; open/preview/ops that join with cwd work unchanged), `view.label =
  "Search results: <query>"` shown in the header, watcher off, `esc` returns to the real listing of the root.

**Wiring**: new actions `finder.scope|hidden|gitignore|open|mark`, `grep.regex|word|field|to_list` (palette-ready, all
bound); default bindings in the `filter`, `finder`, `grep` contexts; `filter.open`, `find.file`, `search.contents`
now run. Text input: keys with no binding in a text context reach `search::on_unbound_key` (so user rebinding wins).
The spinner tick also runs while a search is busy (`SearchState::is_busy`).

## Deviations (with reasons)
1. **`ks-core` now depends on `ks-search`** (and `ks-ui` has it as dev-dependency). The filter must run
   synchronously in `update`/`DirView`, and engine types (`FinderResult`, `GrepEvent`, `PathChange`, `Scope`) travel in
   `Msg`/`Effect` unchanged ("map engine events 1:1"). Cost: nucleo/ignore/grep crates compile with core. `ks-search`
   has no dependency on core, so no cycle.
2. **Finder ticking is a worker thread, not a timer `Msg`** (spec said a ~16-33 ms timer Msg). The thread ticks the
   session only while walking/matching and sleeps otherwise; this keeps matcher waits (`tick(10)`) off the UI loop and
   needs no `FinderTick` message round trip. Same effect: no work while idle, never blocks render.
3. **Scope resolution (`find_git_root` stats) happens on the worker thread**, so `FinderStart` carries `scope + cwd`
   and the resolved root comes back in the snapshot. Consequence: `ctrl-r` cannot skip scopes that resolve to the same
   root (git root without a repository = cwd); the root in the title shows what is searched.
4. Filtered rows are ordered by match score (dirs-first order is not kept while filtering).
5. `ctrl-enter`/`ctrl-o` open, `tab` marks (not `space`, which is text). `o` is text. `alt-enter` avoided (WT).
6. Results list is a pane-local virtual view, not a tab (P7 is concurrent) — see integration notes.
7. Normal-mode hint line is unchanged (still lacks `/ ctrl-p`): P5 owns the hint set and adding entries would churn
   every P1 snapshot. The Filter / Finder / Grep contexts have their own hints.
8. Open-with-default and open-in-editor are placeholders: the runner answers `Effect::OpenInEditor` /
   `Effect::OpenDefault` with the status message "Opening files: wired by P6". Variants have exactly P6's shapes.
9. Size / mtime of results-list entries are not stat'ed (size column is blank for such a list).

## VERIFY results
- Keystroke → results on 500k synthetic paths, through the real worker thread + channel
  (`cargo test -p ks-app --release --test search -- --ignored finder_keystroke --nocapture`, 32 cores): `h` 19.3 ms (the
  worst case, first keystroke), `ha` 9.9, `han` 4.9, `hand` 3.9, `handl` 3.5, `handle` 4.4, `handler` 4.0,
  `handler c` 3.0, `handler cache` 1.5 ms. Budget 25 ms: met. The test asserts it (ignored by default, needs release).
- Reopening the finder on the same root is served from the cache (`from_cache`), tested; the cache sees files created
  while the finder is closed.
- `ctrl-enter` on Windows Terminal arrives as `Enter + CONTROL` through crossterm's console backend (not tested here —
  no interactive terminal); `ctrl-o` is the documented alternative inside the finder.
- Fast typing: 13 keystrokes 10 ms apart start exactly one search (debounce) and the stale generation is dropped.
