# A3: tabs/state persistence, Claude, CI and flaky tests

## Done (per finding)

All six findings still reproduced on the base; each is fixed at the root with a regression test.

1. **Concurrent instances overwrite bookmarks/frecency (major): FIXED.**
   `ks-app/src/persist.rs`: `StateStore::write` now takes a `<file>.toml.lock` (create_new, 3 s wait,
   10 s stale break, `PermissionDenied` counts as contention), re-reads the file and three-way merges
   (base = text this instance last synced, ours = what it wants to write, disk). Base is recorded at
   `load()` and after every write. New `Bookmarks::merge_three_way` (own sets/deletes win, foreign
   additions/deletions survive) and `Frecency::merge_three_way` (ranks are counters: own rank delta is
   added to the disk rank, own forgets are applied, later `last` wins). When nothing foreign changed the
   original text is written verbatim. Tests: two stores on one dir (bookmarks add/delete, frecency
   rank sum), 8 threads writing at once, merge unit tests in ks-core. Decision: the other instance's
   data reaches the running instance's memory only at its next start (the file is always right).
2. **Frecency cap evicts the just-visited entry (minor): FIXED.** `age_if_needed(protect)`: the visited
   key is never dropped by aging or the cap; cap ties break by rank, then `last` (newest kept), then key.
   Test `a_just_visited_directory_survives_the_entry_cap`.
3. **`ps_single_quote` ignores typographic quotes (minor): FIXED.** `ks-claude/src/wt.rs` doubles
   `'` and U+2018/2019/201A/201B. Kept the plan's `-Command` shape (no `-EncodedCommand`), so the
   documented argv is unchanged. Test with `C:\Users\O’Neil\mcp.json` and a `set_env` value.
4. **Changes view shows another file's diff (major): FIXED.** `HookEvent` with the changes overlay on top
   keeps the cursor on the same file (re-resolves its new index), clears the diff when the selected file
   itself was re-edited, and calls `request_diff`. The renderer (`ks-ui/src/claude.rs diff_lines`) also
   refuses a diff whose path is not the highlighted one and shows "Loading diff…". Test
   `a_new_edit_keeps_the_changes_selection_and_never_shows_another_files_diff`.
5. **Failed/immediately exiting pane leaves no trace, `forget()` unused (minor): FIXED.**
   `ks-app/src/claude.rs`: on a non-zero exit the forwarder first sends a final screen snapshot, so
   `ks-core/src/claude.rs on_exited` can put the last two non-blank rows into the status
   ("Claude exited with code 1: No conversation found ..."; Warning level, also logged). The host
   records `LaunchInfo` per launch; a `--resume` that exits non-zero within 30 s calls
   `SessionStore::forget` (spawn_blocking), so the stale id is not retried. Tests: core
   `a_failing_pane_reports_what_it_printed`; integration `a_rejected_resume_shows_the_reason_and_forgets_the_stale_session`
   (fake `claude.cmd` whose `--resume` fails). Not done: restricting the transcript check to the launch
   cwd's project dir (unverified how claude encodes it); the forget-on-failure covers the symptom.
6. **Fresh session overwrites the resumable id (minor): FIXED.** `SessionStore::mode_for` is now one
   locked load-modify-write. A fresh start keeps the old transcript-backed id under a second key
   (`<key>\u{1}confirmed`, same JSON map, so old files stay readable); an unused stored id is reused
   rather than churned; `g r` with an unused current id resumes the confirmed one (and promotes it).
   `forget` clears both. Test `a_fresh_unused_session_does_not_displace_the_resumable_one`.

## Flaky tests

- `bulk_rename_through_an_editor_preview_confirm_and_undo`: it (and the other bulk tests) compared the
  shared system temp dir for `kestrel-bulk-rename-*` files, so any other process (a parallel
  `cargo test`, a running Kestrel) broke it. Reproduced: 12 parallel copies all failed. Fix: `bulk_serial()`
  serialises and points `TMP`/`TEMP` at a private dir once per process; 72 runs under 12x parallel load
  then passed. Slow-machine timeouts (20 s PowerShell start-up under load) fixed by the 60 s `SLACK`.
- `session::concurrent_sets_do_not_lose_entries`: on Windows a lock file being deleted reports
  `PermissionDenied`, which made `StoreLock::acquire` give up and run unlocked; a transient sharing
  violation made `load()` return an empty map, and `rename` had no retry. Now: retry on both, 6 s lock
  wait, retried read and rename. 5/5 passes (and the new persist tests cover the same pattern).
- `a_fake_claude_runs_through_...`: 24 concurrent copies (8 processes x 3) passed after the 60 s
  deadline; no logic race found beyond timeouts.
- `watcher::a_burst_of_changes_is_one_notification`: asserted "at most one extra" after a fixed
  400 ms; on a slow disk the burst spans several 100 ms windows. Now it drains until 600 ms quiet and
  bounds the count by the measured burst duration (`<= 2 + 2 * windows`, and `< 20`).

## Deviations

- Session store keeps one JSON map and adds a suffixed key for the confirmed id instead of a new
  schema (backward compatible, unknown keys are ignored by older builds).
- Concurrent-instance data is merged on write only; in-memory state of the running instance is not
  refreshed from the other instance (would need a file-watch + message; not in scope).
- `-EncodedCommand` not adopted (kept the exact plan shape for `wt`).
